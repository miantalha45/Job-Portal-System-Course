## 2. Set up: send an invitation

Use the owner token from Chapter 33 to invite a fresh email address.

```bash
OWNER_TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"owner@example.com","password":"Password1!"}' \
  | jq -r '.accessToken')

curl -s -X POST http://localhost:3000/api/companies/invitations \
  -H "Authorization: Bearer $OWNER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email":"newmember@example.com","role":"hr_manager"}' \
  | jq .
```

Retrieve the raw token from the database (testing shortcut — in production the invitee gets it via email):

```bash
RAW_TOKEN_HASH=$(psql $DATABASE_URL -t -c \
  "SELECT token_hash FROM invitations WHERE email = 'newmember@example.com';" | tr -d ' ')
echo "Hash in DB: $RAW_TOKEN_HASH"
```

For testing, modify `createInvitation` temporarily to log the raw token to the console, or use the actual email received. The raw token must be used in the next steps.

## 4. Tokens are usable

```bash
MEMBER_TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/accept-invitation \
  -H "Content-Type: application/json" \
  -d '{"token":"<raw-token>","email":"newmember@example.com","password":"Password1!"}' \
  | jq -r '.accessToken')

# The member should now be able to reach company-scoped routes
curl -s -o /dev/null -w "%{http_code}" \
  -H "Authorization: Bearer $MEMBER_TOKEN" \
  http://localhost:3000/api/companies/me
```

Expected: `200` — the member is in the company.
