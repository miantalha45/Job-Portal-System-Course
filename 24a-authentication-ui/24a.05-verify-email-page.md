# 24A.05 — Build Email Verification Feedback

Make verification understandable in all three states: waiting for an email, processing a supplied token, and complete or invalid.

Treat the token as sensitive input. Do not log it, render it in an error message, or retain it longer than the request. If the backend supports resend, apply the same pending and outcome pattern as registration and state when another message can be requested.

Success should offer sign-in or dashboard entry only when the API confirms that path is valid.
