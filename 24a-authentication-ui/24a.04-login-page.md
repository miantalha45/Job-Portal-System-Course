# 24A.04 — Build the Sign-In Page

Use the secure proxy or Server Action from Chapter 4A to submit credentials. Its success path sets the session cookie; the browser page receives only a safe success result and redirect destination.

Provide:

- email and password fields with a password visibility control;
- an inline generic credential error, never an account-enumeration hint;
- a link to registration and a clear pending state;
- focus on the error summary when sign-in fails.

After success, send the user to the validated destination or [24A.06](24a.06-session-and-dashboard-entry.md).
