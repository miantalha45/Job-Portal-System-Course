# Chapter 24A — Authentication Screens and Dashboard Entry

Turn the authentication API from Chapters 20–24 into a calm, usable browser journey. This chapter deliberately owns presentation and navigation; the Express API remains responsible for password checks, token issuance, verification, and authorization.

## Prerequisites

- [Chapter 4A — Frontend Foundations](../04a-frontend-foundations/)
- Chapters 20–24, especially the documented request bodies and error responses

## What you will build

- Registration, sign-in, and email-verification screens
- A session-aware dashboard entry point and a logout action
- Clear field, request, and permission-error states

Do not put access tokens in local storage, session storage, URLs, or React state. Use the httpOnly-cookie and Next.js proxy pattern established in Chapter 4A.

Continue with [24A.02 — Map the authentication journey](24a.02-auth-page-map.md).
