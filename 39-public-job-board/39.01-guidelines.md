# Chapter 39 — The Public Job Board

## What you will build

A public-facing endpoint that lets anyone browse open job listings from verified companies — no authentication required. This is the first surface applicants interact with before they register or apply.

## Learning goals

- Mount a completely unauthenticated router in Express alongside authenticated routes
- Write a JOIN query that filters on two tables simultaneously
- Implement cursor-based pagination for a public list
- Add text search and filter params without breaking pagination

## Prerequisites

- Chapter 36: jobs table with `status` column
- Chapter 37: cursor pagination pattern
- Chapter 38: company panel (companies table with `status` column)

## Files you will create or modify

```
src/modules/public/publicRouter.ts        ← new
src/modules/public/publicService.ts       ← new
app.ts                                    ← mount the /api/public router
```

## Key constraint

`GET /api/public/jobs` must never require an `Authorization` header. Any middleware that validates a token must be absent from this route. The endpoint is rate-limited by the existing global rate limiter only.

## Data visibility rule

A job is visible on the public board if and only if **both** conditions are true:
- `jobs.status = 'open'`
- `companies.status = 'verified'`

If a company is suspended after their jobs are published, those jobs disappear from the board automatically — the query handles this without any additional code.

## Pagination pattern

Identical to Chapter 37: `limit + 1` trick, composite cursor `created_at|id`, base64url encoding. Default limit is 20, max 100.

## Text search (temporary)

Chapter 39 uses `ILIKE` for the `q` param. This is intentionally simple — Chapter 43 replaces it with proper PostgreSQL full-text search. The ILIKE approach is a known interim solution, not a permanent design choice.

## Notes on the response shape

The public response includes `company_name` from the JOIN. It intentionally omits `description` and `screening_questions` on the list view — those come from the single-job detail endpoint to keep list payloads small.
