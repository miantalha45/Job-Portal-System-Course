# Wiring validation into routes

## The pattern

Every route handler that receives external input follows the same shape:

```ts
import { Router } from 'express';
import { validateBody, validateQuery } from '../../shared/validate';
import { createJobSchema, listJobsQuerySchema } from './jobs.schema';

const router = Router();

router.get('/', async (req, res, next) => {
  try {
    const query = validateQuery(listJobsQuerySchema, req.query);
    // query.status, query.page, query.limit are typed and validated
    // ... call service
  } catch (err) {
    next(err);
  }
});

router.post('/', async (req, res, next) => {
  try {
    const body = validateBody(createJobSchema, req.body);
    // body is CreateJobInput — title, description, status, etc. all typed
    // ... call service
  } catch (err) {
    next(err);
  }
});

export { router as jobsRouter };
```

`validateBody` throws `ValidationError` on failure. In Express 4, async errors must be forwarded to `next(err)` — the framework does not automatically catch rejections from async route handlers. The `try/catch` block is the explicit mechanism. Chapter 17 registers the error handler that receives the error from `next(err)` and formats the response.

## What validated data looks like

After `validateBody(createJobSchema, req.body)`:

- `body.title` is `string` — guaranteed non-empty, max 200 chars
- `body.status` is `'draft' | 'open'` — guaranteed to be one of the two values (or defaulted to `'draft'` if omitted)
- `body.deadline` is `string | undefined` — if present, guaranteed to be a valid YYYY-MM-DD date string
- `body.screening_questions` is an array where each item has `text: string`, `type: 'text' | 'boolean' | 'url'`, and `required: boolean`
- `body.attributes` is `Record<string, unknown>` — defaulted to `{}` if omitted

The service function receives this typed object. It does not re-validate any of it.

## Path parameters

Path parameters like `:jobId` need UUID validation. Use `validateParam` from the shared utility — it wraps the result in `ValidationError` the same way `validateBody` and `validateQuery` do, so ch17's single error handler handles all validation failures uniformly:

```ts
import { Router } from 'express';
import { validateParam, uuidParam } from '../../shared/validate';

const router = Router();

router.get('/:jobId', async (req, res, next) => {
  try {
    const jobId = validateParam(uuidParam, req.params.jobId);
    // jobId: string — guaranteed UUID format
    // ... call service
  } catch (err) {
    next(err);
  }
});
```

`uuidParam` is exported from `src/shared/validate.ts` as `z.string().uuid({ message: 'Invalid ID format' })`. Importing it from the shared utility keeps UUID validation consistent across every module that handles path parameters.
