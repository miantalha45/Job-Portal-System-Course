# Zod and the validate utility

## Why Zod

Zod is a TypeScript-first schema library. The key property: a Zod schema is both the runtime validator *and* the TypeScript type definition. You write the schema once; Zod infers the type from it.

```ts
const schema = z.object({ title: z.string().min(1) });
type Input = z.infer<typeof schema>; // { title: string }
```

Without this, every validated input requires two things to stay in sync: the validation logic and the TypeScript type. They drift. Zod collapses them into one.

Other libraries exist. Joi is older, not TypeScript-native. Yup supports schema inference but has a narrower type system. class-validator requires decorators on classes. Zod's advantage for this stack: plain object schemas, excellent TypeScript integration, and all errors reported together — not just the first one.

## Install

```bash
npm install zod@^3.22
```

The `^3.22` lower bound is required: `z.string().date()` (used in the jobs schema below) was added in Zod 3.22.0.

## The validate utility

Create `src/shared/validate.ts`. This file exports a custom error class that ch17's error handler recognises, helpers that run a Zod schema against request data, and a shared UUID validator.

```ts
import { z, ZodSchema, ZodError } from 'zod';

export class ValidationError extends Error {
  constructor(public readonly zodError: ZodError) {
    super('Validation failed');
    this.name = 'ValidationError';
  }
}

export function validateBody<T>(schema: ZodSchema<T>, data: unknown): T {
  const result = schema.safeParse(data);
  if (!result.success) throw new ValidationError(result.error);
  return result.data;
}

export function validateQuery<T>(schema: ZodSchema<T>, data: unknown): T {
  const result = schema.safeParse(data);
  if (!result.success) throw new ValidationError(result.error);
  return result.data;
}

export function validateParam<T>(schema: ZodSchema<T>, data: unknown): T {
  const result = schema.safeParse(data);
  if (!result.success) throw new ValidationError(result.error);
  return result.data;
}

export const uuidParam = z.string().uuid({ message: 'Invalid ID format' });
```

**`safeParse` vs `parse`**: `schema.parse(data)` throws a `ZodError` directly on failure. `schema.safeParse(data)` returns `{ success, data, error }` without throwing — we then throw our own `ValidationError`, wrapping the `ZodError` inside it. This matters in ch17: the error handler checks `err instanceof ValidationError` to distinguish validation failures from other errors. Wrapping gives the error handler a single, Zod-agnostic type — a clean dependency boundary.

**`validateBody`, `validateQuery`, `validateParam`**: These three helpers have the same implementation today. The distinct names communicate *what* each is validating — a request body, a query string, or a path parameter. `validateParam(uuidParam, req.params.jobId)` is clearer than a generic `validate(uuidParam, req.params.jobId)` at the call site.
