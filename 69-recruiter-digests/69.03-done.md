  c.id,
  c.name,

  (SELECT count(*)::int FROM applications a JOIN jobs j ON j.id = a.job_id
   WHERE j.company_id = c.id AND a.created_at >= NOW() - INTERVAL '7 days') AS apps_7d,
  (SELECT count(*)::int FROM interviews iv
   JOIN applications a ON a.id = iv.application_id

## Quiz

1. The digest job fetches all verified companies and emails each owner. A company is verified
   at 07:59 UTC on a Monday, one minute before the digest runs. The owner receives a digest
   for their company even though it was just verified. Is this the correct behaviour? How would
   you exclude companies verified in the last 24 hours from the digest, using only SQL?

2. The correlated subquery for `interviewsThisWeek` uses `date_trunc('week', NOW())`. In
   PostgreSQL, `date_trunc('week', NOW())` returns the Monday of the current week at 00:00 UTC.
   If the server timezone is set to UTC+5, what does `NOW()` return relative to UTC? Would the
   weekly window still be correct? How would you make it timezone-safe?

3. A developer suggests replacing the three correlated subqueries with three separate `db.query`
   calls inside the handler, one per metric, looped per company. List two reasons why the
   single-query correlated approach is better, and one scenario where three separate queries
   would be preferable.
