## Why replace ILIKE

`ILIKE '%typescript%'` works by scanning every row and comparing the string character by character. It cannot use a standard B-tree index — a pattern with a leading wildcard (`%typescript`) prevents index use entirely. On a table with 50,000 jobs, a full ILIKE scan takes hundreds of milliseconds.

Full-text search pre-processes the text into a `tsvector` (a sorted list of lexemes — normalized word roots) at write time. At query time, `plainto_tsquery` parses the search phrase and checks it against the vector. A GIN index makes this check O(log n) instead of O(n).

## Key constraint: only `config.ts` reads `process.env`

The language configuration (`'english'`) is a string constant in the migration and service. If it needs to be configurable, it must come from `config.ts`, not from a direct `process.env` read in the service.

## Notes on `plainto_tsquery` vs `to_tsquery`

- `plainto_tsquery('english', 'typescript engineer')` treats input as natural language. It strips punctuation, normalises words, and ANDs them together: `'typescripton' & 'engin'`.
- `to_tsquery('english', 'typescript & engineer')` requires explicit operators (`&`, `|`, `!`). It will throw an error on plain prose input.

For a job board search box where applicants type free text, `plainto_tsquery` is the correct choice. It never throws on arbitrary input.
