# Chapter 61 — The Admin Panel (Frontend)

## What you will build

Three Next.js App Router pages inside an `/admin` route group that let a logged-in admin view
and act on companies, jobs, and users. Data is fetched via the existing API using the admin's
session cookie. Mutations use Server Actions.

## Learning goals

- Apply the Server Component data-fetching pattern (established in Chapter 38 and 54) to admin
  pages
- Write Server Actions for PATCH mutations — no separate client-side fetch
- Understand why the admin panel is a separate route group, not a separate application

## Prerequisites

- Chapters 59–60: admin API endpoints in place
- Chapter 38: Next.js session cookie pattern (httpOnly cookie carrying the JWT)
- Chapter 54: applicant panel as a reference for Server Component + Server Action structure

## Implementation

### app/admin/layout.tsx

```tsx
import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';

// Verify the user is an admin before rendering any admin page
export default async function AdminLayout({ children }: { children: React.ReactNode }) {
  const token = cookies().get('token')?.value;
  if (!token) redirect('/login');

  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/auth/me`, {
    headers: { Authorization: `Bearer ${token}` },
    cache: 'no-store',
  });

  if (!res.ok) redirect('/login');

  const { user } = await res.json();
  if (user.role !== 'admin') redirect('/');

  return (
    <html>
      <body>
        <nav>
          <a href="/admin/companies">Companies</a>
          <a href="/admin/jobs">Jobs</a>
          <a href="/admin/users">Users</a>
        </nav>
        <main>{children}</main>
      </body>
    </html>
  );
}
```

Note: `NEXT_PUBLIC_API_URL` is set in the Next.js environment (`.env.local`). Only the layout
reads this env var — it is a Next.js configuration concern, not application logic that belongs
in `config.ts`. The Express API never touches Next.js env vars.

### app/admin/companies/page.tsx

```tsx
import { cookies } from 'next/headers';
import { verifyCompany, suspendCompany } from './actions';

async function fetchCompanies(status?: string) {
  const token = cookies().get('token')?.value ?? '';
  const url = status
    ? `${process.env.NEXT_PUBLIC_API_URL}/api/admin/companies?status=${status}`
    : `${process.env.NEXT_PUBLIC_API_URL}/api/admin/companies`;

  const res = await fetch(url, {
    headers: { Authorization: `Bearer ${token}` },
    cache: 'no-store',
  });
  const data = await res.json();
  return data.companies as Array<{
    id: string; name: string; status: string; owner_email: string; created_at: string;
  }>;
}

export default async function CompaniesPage({
  searchParams,
}: {
  searchParams: { status?: string };
}) {
  const companies = await fetchCompanies(searchParams.status);

  return (
    <section>
      <h1>Companies</h1>
      <div>
        <a href="/admin/companies">All</a>
        <a href="/admin/companies?status=pending">Pending</a>
        <a href="/admin/companies?status=verified">Verified</a>
        <a href="/admin/companies?status=suspended">Suspended</a>
      </div>
      <table>
        <thead>
          <tr>
            <th>Name</th><th>Status</th><th>Owner</th><th>Created</th><th>Actions</th>
          </tr>
        </thead>
        <tbody>
          {companies.map((c) => (
            <tr key={c.id}>
              <td>{c.name}</td>
              <td>{c.status}</td>
              <td>{c.owner_email}</td>
              <td>{new Date(c.created_at).toLocaleDateString()}</td>
              <td>
                <form action={verifyCompany}>
                  <input type="hidden" name="id" value={c.id} />
                  <button type="submit" disabled={c.status === 'verified'}>Verify</button>
                </form>
                <form action={suspendCompany}>
                  <input type="hidden" name="id" value={c.id} />
                  <button type="submit" disabled={c.status === 'suspended'}>Suspend</button>
                </form>
              </td>
            </tr>
          ))}
        </tbody>
      </table>
    </section>
  );
}
```

### app/admin/companies/actions.ts

```ts
'use server';

import { cookies } from 'next/headers';
import { revalidatePath } from 'next/cache';

async function patchCompany(id: string, action: 'verify' | 'suspend') {
  const token = cookies().get('token')?.value ?? '';
  await fetch(
    `${process.env.NEXT_PUBLIC_API_URL}/api/admin/companies/${id}/${action}`,
    { method: 'PATCH', headers: { Authorization: `Bearer ${token}` } }
  );
  revalidatePath('/admin/companies');
}

export async function verifyCompany(formData: FormData) {
  await patchCompany(formData.get('id') as string, 'verify');
}

export async function suspendCompany(formData: FormData) {
  await patchCompany(formData.get('id') as string, 'suspend');
}
```

### app/admin/jobs/page.tsx

import { cookies } from 'next/headers';
import { closeJob } from './actions';

### app/admin/jobs/actions.ts

```ts
'use server';

import { cookies } from 'next/headers';
import { revalidatePath } from 'next/cache';

export async function closeJob(formData: FormData) {
  const token = cookies().get('token')?.value ?? '';
  const id = formData.get('id') as string;
  await fetch(
    `${process.env.NEXT_PUBLIC_API_URL}/api/admin/jobs/${id}/close`,
    { method: 'PATCH', headers: { Authorization: `Bearer ${token}` } }
  );
  revalidatePath('/admin/jobs');
}
```

### app/admin/users/page.tsx and actions.ts

Follow the same pattern as companies: `fetchUsers()` → table → forms with hidden `id` inputs →
Server Actions for `suspendUser` (PATCH `.../suspend`) and `activateUser` (PATCH `.../activate`).
Use `revalidatePath('/admin/users')` after each action.

---

## Auth pattern

No new auth logic is introduced. The layout reads the httpOnly cookie (set at login in Chapter
38), passes it as a `Bearer` header to the API, and the API's `authMiddleware` validates it.
The layout redirects to `/login` on any auth failure. Individual pages and actions inherit this
protection because they are rendered inside the layout.

---

## No `process.env` in Express modules

`NEXT_PUBLIC_API_URL` is read only in Next.js files (`app/admin/**`). No file inside
`src/modules/` or `src/shared/` reads any environment variable directly — those go through
`config.ts` exclusively.
