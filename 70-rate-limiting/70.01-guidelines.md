# Chapter 70 — Rate Limiting & Abuse Protection

## What you will build

A global rate limiter on all routes and a stricter limiter on auth endpoints. Both use a Redis
store so limits are shared across multiple server instances and survive restarts.

## Learning goals

- Apply `express-rate-limit` with a Redis store
- Distinguish global limits from route-specific limits
- Return a well-formed 429 response consistent with the rest of the error format

## Prerequisites

- Chapter 6: `config.ts` — add two new fields
- `src/shared/redis.ts` exports the Redis client
- Chapter 17: global error handler format `{ error: { code, message } }`

## Config additions (src/shared/config.ts)

```ts
export default {
  // ... existing fields ...
  RATE_LIMIT_WINDOW_MS: parseInt(process.env.RATE_LIMIT_WINDOW_MS ?? '60000', 10),
  RATE_LIMIT_MAX: parseInt(process.env.RATE_LIMIT_MAX ?? '100', 10),
};
```

These two fields are the only new `process.env` reads. They live in `config.ts` exactly like
every other config value. No other file reads `process.env`.

## Implementation

### src/shared/rateLimiter.ts

```ts
import rateLimit from 'express-rate-limit';
import { RedisStore } from '@express-rate-limit/redis';
import { redis } from './redis';
import config from './config';

// Global limiter: applies to all routes
export const globalLimiter = rateLimit({
  windowMs: config.RATE_LIMIT_WINDOW_MS,
  max: config.RATE_LIMIT_MAX,
  standardHeaders: true,    // include RateLimit-* headers in response
  legacyHeaders: false,
  store: new RedisStore({
    sendCommand: (...args: string[]) => redis.sendCommand(args),
  }),
  handler: (_req, res) => {
    res.status(429).json({
      error: {
        code: 'RATE_LIMITED',
        message: 'Too many requests',
      },
    });
  },
});

// Stricter limiter for auth routes: 10 requests per 15 minutes
export const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 10,
  standardHeaders: true,
  legacyHeaders: false,
  store: new RedisStore({
    sendCommand: (...args: string[]) => redis.sendCommand(args),
    prefix: 'rl:auth:',   // separate Redis key namespace from global limiter
  }),
  handler: (_req, res) => {
    res.status(429).json({
      error: {
        code: 'RATE_LIMITED',
        message: 'Too many requests',
      },
    });
  },
});
```

### app.ts — apply limiters

```ts
import { globalLimiter, authLimiter } from './shared/rateLimiter';

// Global limiter — before any route
app.use(globalLimiter);

// Auth-specific limiter — on individual auth routes
app.post('/api/auth/login', authLimiter, authRouter.login);
app.post('/api/auth/register', authLimiter, authRouter.register);
app.post('/api/auth/verify-email', authLimiter, authRouter.verifyEmail);
app.post('/api/auth/resend-verification', authLimiter, authRouter.resendVerification);

// Mount full auth router (non-limited endpoints like /refresh, /logout)
app.use('/api/auth', authRouter);
```

If the auth router is mounted as a single unit, apply the auth limiter differently:

```ts
// Alternative: apply authLimiter inside the auth router for specific routes
// In auth.routes.ts:
router.post('/login', authLimiter, loginHandler);
router.post('/register', authLimiter, registerHandler);
```

## Response headers

When a request is within the limit, the response includes:

```
RateLimit-Limit: 100
RateLimit-Remaining: 97
RateLimit-Reset: 2026-06-07T10:01:00.000Z
```

When the limit is exceeded:

```
HTTP/1.1 429 Too Many Requests
RateLimit-Limit: 10
RateLimit-Remaining: 0
Retry-After: 847
```

## No `process.env` in this module

`rateLimiter.ts` reads only from `config` (imported from `./config`). The two new env vars
(`RATE_LIMIT_WINDOW_MS`, `RATE_LIMIT_MAX`) are added to `config.ts` and nowhere else.
