# Chapter 70 — Definition of Done

## Verifiable checklist

```bash
# 1. Packages installed
cat package.json | grep -E 'express-rate-limit|@express-rate-limit'
# Expected: both packages listed

# 2. TypeScript compiles with zero errors
npx tsc --noEmit

# 3. Config fields present
grep 'RATE_LIMIT' src/shared/config.ts
# Expected: RATE_LIMIT_WINDOW_MS and RATE_LIMIT_MAX

# 4. No process.env in rateLimiter.ts
grep 'process\.env' src/shared/rateLimiter.ts
# Expected: no output

# 5. Global limiter in app.ts before routes
grep -n 'globalLimiter' src/app.ts
# Expected: a line number before any app.use('/api/...')

# 6. Test global limiter with low max (set env var for this test run)
RATE_LIMIT_MAX=5 npm run dev &
API_PID=$!
sleep 2

for i in {1..6}; do
  CODE=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/health)
  echo "Request $i: $CODE"
done
# Expected: 200 200 200 200 200 429

kill $API_PID

# 7. Test auth limiter (11 requests to /api/auth/login)
npm run dev &
API_PID=$!
sleep 2

PASS_COUNT=0
FAIL_COUNT=0
for i in {1..11}; do
  CODE=$(curl -s -o /dev/null -w "%{http_code}" \
    -X POST http://localhost:3000/api/auth/login \
    -H 'Content-Type: application/json' \
    -d '{"email":"nobody@example.com","password":"wrong"}')
  echo "Auth request $i: $CODE"
  [ "$CODE" = "429" ] && FAIL_COUNT=$((FAIL_COUNT+1))
done
echo "429 responses: $FAIL_COUNT"
# Expected: 429 responses: 1 (the 11th request)

kill $API_PID

# 8. Confirm 429 body matches the error format
curl -s -X POST http://localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"x@x.com","password":"wrong"}' | jq '.error.code'
# (After triggering the rate limit — may need to wait for counter reset first)
# Expected: "RATE_LIMITED"

# 9. Confirm RateLimit headers are present on normal responses
curl -sI http://localhost:3000/health | grep -i ratelimit
# Expected: RateLimit-Limit, RateLimit-Remaining, RateLimit-Reset headers

# 10. Confirm Redis has rate limit keys
redis-cli KEYS "rl:*" | head -5
# Expected: keys like rl:127.0.0.1:... and rl:auth:...
```

## Quiz

1. The global limiter uses a window of 60 seconds and a max of 100 requests. A user sends 100
   requests at T=0:30. All succeed. At T=1:00 (30 seconds later), they send 1 more request.
   Does it succeed or get rate limited? Explain how the sliding window algorithm differs from
   a fixed window in this scenario.

2. The `handler` function in both limiters returns the same JSON shape as the global error
   handler from Chapter 17. Why is this important, and what would a frontend developer expect
   to happen if the shape were different (e.g., just a string `"Too many requests"`)?

3. An attacker distributes their requests across 100 different IP addresses (a botnet). How
   does rate limiting per IP protect against concentrated attacks but fail against distributed
   attacks? What additional mechanism would you add to protect against distributed credential
   stuffing (think: application-layer, not network-layer)?
