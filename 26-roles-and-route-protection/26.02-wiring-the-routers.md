# Build: Wiring the routers

## The pattern

`router.use(authMiddleware, requireRole(...))` placed before all route definitions is the complete guard for a router. Everything registered on the router after this line is protected. This chapter applies that pattern to three routers.

---

## `src/modules/companies/companies.routes.ts`

```ts
import { Router } from 'express';
import { authMiddleware } from '../../shared/auth-middleware';
import { requireRole } from '../../shared/require-role';

const router = Router();

// Every route on this router requires a valid token with role 'recruiter'.
router.use(authMiddleware, requireRole('recruiter'));

// Placeholder — real endpoints are added in later chapters.
router.get('/', (_req, res) => {
  res.status(501).json({ error: 'Not Implemented' });
});

export { router as companiesRouter };
```

## `src/app.ts` — mounting the routers

Import the three routers and mount them at their base paths. Keep any existing routers (auth, health) in place.

```ts
import { companiesRouter } from './modules/companies/companies.routes';
import { applicantsRouter } from './modules/applicants/applicants.routes';
import { adminRouter } from './modules/admin/admin.routes';

// ... existing imports ...

app.use('/api/companies', companiesRouter);
app.use('/api/applicants', applicantsRouter);
app.use('/api/admin', adminRouter);
```

The full `app.ts` after these additions (existing sections abbreviated):

```ts
import express from 'express';
import { authRouter } from './modules/auth/auth.routes';
import { companiesRouter } from './modules/companies/companies.routes';
import { applicantsRouter } from './modules/applicants/applicants.routes';
import { adminRouter } from './modules/admin/admin.routes';
import { errorHandler } from './shared/error-handler';

const app = express();
app.use(express.json());

app.get('/health', (_req, res) => res.json({ status: 'ok' }));
app.use('/api/auth', authRouter);
app.use('/api/companies', companiesRouter);
app.use('/api/applicants', applicantsRouter);
app.use('/api/admin', adminRouter);

app.use(errorHandler);

export { app };
```

## How the guard works at the router level

When Express receives `GET /api/companies/`, it strips the `/api/companies` prefix and hands `/` to `companiesRouter`. Before the router matches any route, it runs every `router.use` handler registered on that router in order.

`router.use(authMiddleware, requireRole('recruiter'))` registers two middleware functions as a single `use` call. Express runs them in sequence. `authMiddleware` runs first — if the token is missing or invalid, it calls `next(UnauthorizedError)` and Express skips the rest of the chain including every route handler. If the token is valid, `requireRole('recruiter')` runs — if the role is not `recruiter`, it calls `next(ForbiddenError)`.

Only if both middleware call `next()` without an error does Express proceed to match routes and run the route handler.

This sequence is identical to placing `authMiddleware, requireRole('recruiter')` on every individual route. The difference is location: on the router, not on each route.

## What a wrong-role request looks like

A user with `role: 'applicant'` calls `GET /api/companies/`:

```
GET /api/companies/ HTTP/1.1
Authorization: Bearer <applicant-token>
```

Response:

```json
HTTP/1.1 403 Forbidden

{
  "error": "Insufficient role"
}
```

`authMiddleware` passes (the token is valid). `requireRole('recruiter')` fails (the role is `applicant`). The 501 placeholder handler never runs. The error handler converts `ForbiddenError` to a 403 response.

A request with no token at all:

```
GET /api/companies/ HTTP/1.1
```

Response:

```json
HTTP/1.1 401 Unauthorized

{
  "error": "No token provided"
}
```

`authMiddleware` fails immediately. `requireRole` never runs.

## TypeScript check

After creating the three files and updating `app.ts`, run:

```bash
npx tsc --noEmit
```

Zero errors means the imports, exports, and types all resolve correctly. If `router.use` produces a type error, confirm the middleware signatures match `(req, res, next) => void` — Express's `Router.use` accepts this overload.
