# Chapter 55 — The Application Stage Pipeline

## What you will build

An endpoint that moves an application through its stage pipeline. Transitions are validated — only forward moves are allowed, and terminal stages cannot be left.

## Learning goals

- Encode a finite state machine as an ordered array
- Validate transitions: only forward, never backward, never from a terminal stage
- Scope the endpoint to the owning company (recruiter cannot touch another company's applications)
- Return the updated application

## Prerequisites

- Chapter 36: `assertJobOwnership` pattern (or equivalent ownership check from the companies module)
- Chapter 26: `requireRole('recruiter')` guard
- `applications` table with the `stage` CHECK constraint

## Stage order

```ts
const STAGE_ORDER = [
  'applied',
  'screening',
  'interview',
  'final_interview',
  'offer',
  'hired',
  'rejected',
] as const;

type Stage = typeof STAGE_ORDER[number];
```

`hired` and `rejected` are terminal stages — no transition out of them is allowed.

## Transition rules

1. The `targetStage` must be a valid stage name (in `STAGE_ORDER`)
2. The current stage must not be `hired` or `rejected` (terminal)
3. The `targetStage` index must be **greater than** the current stage index (forward only)
   - Exception: `rejected` can be reached from any non-terminal stage (it is a special terminal that can be entered from any point)

Simplified: `targetStage` must come after `currentStage` in the array, with `rejected` reachable from any non-terminal position.

## Implementation

### Ownership check

```ts
// applications.repo.ts
export async function findApplicationForCompany(
  applicationId: string,
  companyId: string
) {
  const result = await db.query(
    `SELECT a.id, a.job_id, a.applicant_id, a.stage, a.status
     FROM applications a
     JOIN jobs j ON j.id = a.job_id
     WHERE a.id = $1 AND j.company_id = $2`,
    [applicationId, companyId]
  );
  return result.rows[0] ?? null;
}

export async function updateApplicationStage(
  applicationId: string,
  stage: string
) {
  const result = await db.query(
    `UPDATE applications SET stage = $1 WHERE id = $2
     RETURNING id, job_id, applicant_id, stage, status, created_at`,
    [stage, applicationId]
  );
  return result.rows[0] ?? null;
}
```

### Transition validation

```ts
// applications.service.ts
import { ValidationError, NotFoundError, ForbiddenError } from '../../shared/errors';

const STAGE_ORDER = [
  'applied', 'screening', 'interview', 'final_interview', 'offer', 'hired', 'rejected'
] as const;
type Stage = typeof STAGE_ORDER[number];

const TERMINAL_STAGES = new Set<Stage>(['hired', 'rejected']);

function assertValidTransition(current: Stage, target: Stage) {
  if (TERMINAL_STAGES.has(current)) {
    throw new ValidationError(`Cannot transition from terminal stage '${current}'`);
  }
  if (!STAGE_ORDER.includes(target)) {
    throw new ValidationError(`'${target}' is not a valid stage`);
  }
  // 'rejected' can be reached from any non-terminal stage
  if (target === 'rejected') return;

  const currentIdx = STAGE_ORDER.indexOf(current);
  const targetIdx  = STAGE_ORDER.indexOf(target);

  if (targetIdx <= currentIdx) {
    throw new ValidationError(
      `Cannot move backward from '${current}' to '${target}'`
    );
  }
}
```

### Service function

```ts
export async function moveApplicationStage(
  recruiterCompanyId: string,
  applicationId: string,
  targetStage: Stage
) {
  const application = await repo.findApplicationForCompany(applicationId, recruiterCompanyId);
  if (!application) throw new NotFoundError('Application not found');
  if (application.status === 'withdrawn') {
    throw new ValidationError('Cannot change stage of a withdrawn application');
  }

  assertValidTransition(application.stage as Stage, targetStage);

  return repo.updateApplicationStage(applicationId, targetStage);
}
```

### Route

```ts
// companies/applications.routes.ts
import { Router } from 'express';
import { requireAuth } from '../../shared/middleware/requireAuth';
import { requireRole } from '../../shared/middleware/requireRole';
import * as service from './applications.service';

const router = Router();
router.use(requireAuth, requireRole('recruiter'));

router.patch('/:id/stage', async (req, res, next) => {
  try {
    const { stage } = req.body;
    const updated = await service.moveApplicationStage(
      req.user!.companyId,  // from the JWT or recruiter lookup
      req.params.id,
      stage
    );
    res.json(updated);
  } catch (err) {
    next(err);
  }
});

export default router;
```

## Getting `companyId` from the recruiter token

The recruiter's JWT should include `companyId`. If it does not (depending on how Chapter 31 was implemented), look it up:

```ts
// In the service, before moveApplicationStage:
const member = await db.query(
  `SELECT company_id FROM company_members WHERE user_id = $1`,
  [req.user!.userId]
);
if (!member.rows[0]) throw new ForbiddenError('Not a company member');
const companyId = member.rows[0].company_id;
```

This adds one query per request but avoids embedding mutable data (company membership) in the JWT.
