# Chapter 73 — Definition of Done

## Verifiable checklist

```bash
# 1. Packages installed
cat package.json | grep -E '"helmet"|"cors"'
# Expected: both packages listed

# 2. TypeScript compiles with zero errors
npx tsc --noEmit

# 3. X-Content-Type-Options header is present
curl -sI http://localhost:3000/health | grep -i 'x-content-type'
# Expected: X-Content-Type-Options: nosniff

# 4. X-Frame-Options header is present
curl -sI http://localhost:3000/health | grep -i 'x-frame'
# Expected: X-Frame-Options: SAMEORIGIN

# 5. X-Powered-By header is ABSENT
curl -sI http://localhost:3000/health | grep -i 'x-powered'
# Expected: no output

# 6. CORS allows the configured frontend origin
curl -H "Origin: http://localhost:3001" \
  -H "Access-Control-Request-Method: GET" \
  -X OPTIONS http://localhost:3000/api/jobs -sI | grep 'Access-Control-Allow-Origin'
# Expected: Access-Control-Allow-Origin: http://localhost:3001

# 7. CORS blocks an unknown origin
curl -H "Origin: http://evil.com" \
  -H "Access-Control-Request-Method: GET" \
  -X OPTIONS http://localhost:3000/api/jobs -sI | grep 'Access-Control-Allow-Origin'
# Expected: no output (header absent)

# 8. SQL injection attempt returns 0 results (not all jobs)
curl -s "http://localhost:3000/api/jobs?status=open' OR '1'='1" | jq '.jobs | length'
# Expected: 0

# 9. Normal query returns results
curl -s "http://localhost:3000/api/jobs?status=open" | jq '.jobs | length'
# Expected: N > 0 (some open jobs)

# 10. FRONTEND_URL is in config.ts
grep 'FRONTEND_URL' src/shared/config.ts
# Expected: the config field

# 11. No process.env in app.ts (except any that were there before Chapter 6)
grep 'process\.env' src/app.ts
# Expected: no output

# 12. Strict-Transport-Security header present
curl -sI http://localhost:3000/health | grep -i strict
# Expected: Strict-Transport-Security: max-age=...
```

## Log-it

1. Look at the full list of headers returned by `curl -I http://localhost:3000/health` before
   and after adding Helmet. Write down every header that is new. For each one, look up its
   purpose in the MDN Web Docs and write one sentence explaining what attack it mitigates.

2. CORS is a browser mechanism — `curl` ignores it completely. Demonstrate this: call
   `curl -H "Origin: http://evil.com" http://localhost:3000/api/jobs`. The request succeeds.
   Write down why CORS alone is not sufficient to protect the API and what mechanism provides
   the real protection for authenticated endpoints.

## Quiz

1. Helmet sets `X-Frame-Options: SAMEORIGIN`. A product manager requests that the job board
   page be embeddable in a partner site's iframe for marketing purposes. What change to the
   Helmet configuration would allow iframing from one specific partner origin but not from
   all other sites?

2. The CORS configuration uses `credentials: true`. This is required for the browser to send
   the httpOnly session cookie with cross-origin requests. What header must the server set
   alongside `Access-Control-Allow-Origin` when `credentials: true` is used, and why does
   `Access-Control-Allow-Origin: *` become invalid when credentials are involved?

3. Zod's `schema.parse(req.body)` strips unknown fields. A developer uses `schema.passthrough()`
   instead, which preserves unknown fields. The register route passes the parsed body directly
   to the INSERT query. Describe the specific SQL injection or data integrity attack this
   enables, and explain why the Zod allow-list prevents it.
