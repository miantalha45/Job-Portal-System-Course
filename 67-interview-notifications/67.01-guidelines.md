# Chapter 67 — Interview Notification Jobs

## What you will build

Move the inline interview notification email from Chapter 56 into a background job. The HTTP
response for `POST /api/interviews` now returns before the notification email is sent.

## Learning goals

- Apply the async migration pattern a second time (same pattern as Chapter 64)
- Recognise that the migration is always the same: find inline send → replace with queue.add
- Complete the "async migration" of all email calls in the system

## Prerequisites

- Chapter 56: `scheduleInterview` service function with inline `sendInterviewNotification`
- Chapter 63–64: queue and worker in place

## Implementation

### src/modules/companies/interviews.service.ts — before

```ts
// Chapter 56 version — inline send (REMOVE this)
await mailer.sendInterviewNotification(
  applicantEmail,
  scheduledAt,
  meetingLink
);
```

### src/modules/companies/interviews.service.ts — after

```ts
import queue from '../../shared/queue';

// Replace the inline call with:
await queue.add('send-interview-notification', {
  applicantEmail,
  scheduledAt: scheduledAt.toISOString(),   // serialize Date to string for JSON
  meetingLink,
});
```

Always serialize `Date` objects to ISO strings before putting them in a job payload. BullMQ
serializes the payload to JSON. `JSON.stringify(new Date())` produces a string, but relying on
implicit serialization leads to subtle bugs when the worker deserializes the payload.

### src/worker/worker.ts — add the handler

```ts
import { sendInterviewNotification } from '../shared/mailer';

case 'send-interview-notification': {
  const { applicantEmail, scheduledAt, meetingLink } = job.data;
  await sendInterviewNotification(applicantEmail, scheduledAt, meetingLink);
  break;
}
```

`sendInterviewNotification` already exists in `mailer.ts` from Chapter 56. No changes needed
in the mailer.

## No `process.env` in this module

Both are accessed via `config.ts`.
