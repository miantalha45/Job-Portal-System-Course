# Chapter 57 — Interview Feedback & Outcomes

## What you will build

An endpoint that records a recruiter's feedback on an interview and moves the application to the next stage (if moved forward) or to `rejected` (if not).

## Learning goals

- Update a child record (`interviews`) and its parent (`applications`) in a coordinated way
- Enforce scoping: the interview must belong to the recruiter's company
- Reuse the stage advancement logic from Chapter 55

## Prerequisites

- Chapter 55: `STAGE_ORDER`, `assertValidTransition`, and `updateApplicationStage` from the companies applications service/repo
- Chapter 56: `interviews` table in place

## Endpoint

```
PATCH /api/companies/interviews/:id/feedback
Authorization: Bearer <recruiter token>
Content-Type: application/json

{
  "feedback": "Strong technical skills, good communication.",
  "outcome": "moved_forward"
}
```

Body values:
- `feedback`: string, required
- `outcome`: `"moved_forward"` | `"rejected"`, required

Response (HTTP 200):

```json
{
  "interview": {
    "id": "uuid",
    "application_id": "uuid",
    "feedback": "Strong technical skills, good communication.",
    "outcome": "moved_forward",
    ...
  },
  "application": {
    "id": "uuid",
    "stage": "final_interview",
    ...
  }
}
```

## Implementation

### applications.repo.ts — new functions

```ts
export async function findInterviewForCompany(
  interviewId: string,
  companyId: string
) {
  const result = await db.query(
    `SELECT
       i.id, i.application_id, i.scheduled_at, i.meeting_link,
       i.notes, i.feedback, i.outcome,
       a.stage AS application_stage,
       a.status AS application_status,
       j.company_id
     FROM interviews i
     JOIN applications a ON a.id = i.application_id
     JOIN jobs        j ON j.id = a.job_id
     WHERE i.id = $1 AND j.company_id = $2`,
    [interviewId, companyId]
  );
  return result.rows[0] ?? null;
}

export async function updateInterviewFeedback(
  interviewId: string,
  feedback: string,
  outcome: 'moved_forward' | 'rejected'
) {
  const result = await db.query(
    `UPDATE interviews
     SET feedback = $1, outcome = $2
     WHERE id = $3
     RETURNING id, application_id, scheduled_at, meeting_link, notes, feedback, outcome, created_at`,
    [feedback, outcome, interviewId]
  );
  return result.rows[0] ?? null;
}
```

### applications.service.ts — recordInterviewFeedback

```ts
export async function recordInterviewFeedback(
  companyId: string,
  interviewId: string,
  body: { feedback: string; outcome: 'moved_forward' | 'rejected' }
) {
  const interview = await repo.findInterviewForCompany(interviewId, companyId);
  if (!interview) throw new NotFoundError('Interview not found');

  if (interview.outcome !== 'pending') {
    throw new ValidationError('Feedback has already been recorded for this interview');
  }

  if (interview.application_status === 'withdrawn') {
    throw new ValidationError('Cannot record feedback for a withdrawn application');
  }

  // Update the interview record
  const updatedInterview = await repo.updateInterviewFeedback(
    interviewId,
    body.feedback,
    body.outcome
  );

  // Advance or terminate the application based on outcome
  let updatedApplication: Record<string, unknown> | null = null;

  if (body.outcome === 'rejected') {
    updatedApplication = await repo.updateApplicationStage(interview.application_id, 'rejected');
  } else {
    // outcome === 'moved_forward': advance to the next stage
    const currentStage = interview.application_stage as Stage;
    const currentIdx   = STAGE_ORDER.indexOf(currentStage);
    const nextStage    = STAGE_ORDER[currentIdx + 1];

    if (!nextStage || TERMINAL_STAGES.has(currentStage)) {
      // Already at a terminal or no next stage — do not change stage
      // (This happens if feedback is recorded on an application already at 'offer')
    } else {
      updatedApplication = await repo.updateApplicationStage(interview.application_id, nextStage);
    }
  }

  return { interview: updatedInterview, application: updatedApplication };
}
```

If the applications router is mounted at `/api/companies/applications`, the interview feedback route will be at `/api/companies/applications/interviews/:id/feedback`. To get the cleaner URL `/api/companies/interviews/:id/feedback`, mount a separate router at `/api/companies/interviews` in `app.ts`.

## Outcome → stage mapping

| outcome         | Action on application stage |
|-----------------|----------------------------|
| `moved_forward` | Advance to the next stage in `STAGE_ORDER` |
| `rejected`      | Set stage to `rejected` |

"Next stage" is determined by the application's current stage at the time feedback is recorded — not at the time the interview was scheduled. If the application advanced to `final_interview` between scheduling and feedback, `moved_forward` advances it to `offer`.

---

## Idempotency of feedback

The service rejects feedback if `interview.outcome !== 'pending'`. This prevents overwriting feedback that has already been submitted. If a recruiter submits feedback twice (network retry), the second request returns a 400. This is intentional — feedback is an important record; overwriting it silently would be a data integrity problem.
