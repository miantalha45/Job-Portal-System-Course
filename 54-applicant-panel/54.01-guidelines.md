# Chapter 54 — The Applicant Panel (Frontend)

## What you will build

A set of Next.js App Router pages that let an applicant browse jobs, shortlist them, apply, upload a résumé, and track their applications. This frontend mirrors the API endpoints built in Chapters 46–53.

## Learning goals

- Apply the App Router patterns established in Chapter 38 (company panel) to the applicant flow
- Implement direct-to-S3 résumé upload from the browser using a presigned URL
- Show application stage as a badge without a full status management UI

## Prerequisites

- Chapter 38: Next.js App Router, httpOnly cookie auth, server actions or API routes pattern in place
- Chapters 46–53: all applicant API endpoints working
- Chapter 48: presigned URL upload flow

## Pages to build

| Route                        | Auth required | Description                                          |
|------------------------------|---------------|------------------------------------------------------|
| `/jobs`                      | No            | Public job board — list open jobs, links to detail   |
| `/jobs/[id]`                 | No            | Job detail — "Apply" and "Shortlist" buttons          |
| `/dashboard/shortlist`       | Yes (applicant) | List shortlisted jobs                              |
| `/dashboard/applications`    | Yes (applicant) | List applications with current stage badge          |
| `/dashboard/profile`         | Yes (applicant) | Profile editor + résumé upload                     |

## Auth pattern (same as Chapter 38)

The access token is stored in an httpOnly cookie. Server Components read the cookie and pass it to fetch calls. Client Components that need to trigger actions use Server Actions or route handlers.

```ts
// app/lib/api.ts
import { cookies } from 'next/headers';

export async function apiFetch<T>(path: string, init?: RequestInit): Promise<T> {
  const token = cookies().get('accessToken')?.value;
  const res = await fetch(`${process.env.NEXT_PUBLIC_API_URL}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...init?.headers,
    },
  });
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new Error(body.message ?? `HTTP ${res.status}`);
  }
  return res.json();
}
```

Note: `process.env.NEXT_PUBLIC_API_URL` is the one case where `process.env` is read outside `config.ts`. This is acceptable in Next.js — `NEXT_PUBLIC_*` variables are a Next.js convention for browser-exposed env vars. The backend API server still reads all env vars only through `config.ts`.

```tsx
export default async function DashboardLayout({ children }: { children: React.ReactNode }) {
```

## Public job board (`/jobs`)

```tsx
// app/jobs/page.tsx
import { apiFetch } from '../lib/api';
import Link from 'next/link';

type Job = { id: string; title: string; company: { name: string }; created_at: string };

export default async function JobsPage() {
  const { jobs } = await apiFetch<{ jobs: Job[] }>('/api/public/jobs');

  return (
    <main>
      <h1>Open Positions</h1>
      <ul>
        {jobs.map((job) => (
          <li key={job.id}>
            <Link href={`/jobs/${job.id}`}>
              {job.title} — {job.company.name}
            </Link>
          </li>
        ))}
      </ul>
    </main>
  );
}
```

This page is a Server Component. It calls the public job board API (no auth token needed). The `apiFetch` helper skips the Authorization header if no cookie is present.

## Job detail with Apply and Shortlist (`/jobs/[id]`)

```tsx
// app/jobs/[id]/page.tsx
'use client';
import { useState } from 'react';

export default function JobDetailPage({ params }: { params: { id: string } }) {
  const [status, setStatus] = useState<string | null>(null);

  async function handleApply() {
    const res = await fetch('/api/applicants/apply', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ jobIds: [params.id], answers: {} }),
    });
    const data = await res.json();
    setStatus(res.ok ? 'Applied!' : data.message ?? 'Error');
  }

  async function handleShortlist() {
    const res = await fetch('/api/applicants/shortlist', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ jobId: params.id }),
    });
    setStatus(res.ok ? 'Shortlisted!' : 'Already shortlisted or error');
  }

  return (
    <main>
      <h1>Job {params.id}</h1>
      <button onClick={handleApply}>Apply</button>
      <button onClick={handleShortlist}>Shortlist</button>
      {status && <p>{status}</p>}
    </main>
  );
}
```

This is a minimal implementation. Extend it by loading job details from the API (e.g., `GET /api/public/jobs/:id` — you may need to add this endpoint, or derive it from the list query).

## Applications list (`/dashboard/applications`)

```tsx
// app/dashboard/applications/page.tsx
import { apiFetch } from '../../lib/api';

const STAGE_COLOURS: Record<string, string> = {
  applied:         'bg-gray-200',
  screening:       'bg-blue-200',
  interview:       'bg-yellow-200',
  final_interview: 'bg-orange-200',
  offer:           'bg-green-200',
  hired:           'bg-green-500',
  rejected:        'bg-red-200',
};

export default async function ApplicationsPage() {
  const { applications } = await apiFetch<{ applications: any[] }>('/api/applicants/applications');

  return (
    <main>
      <h1>My Applications</h1>
      <ul>
        {applications.map((app) => (
          <li key={app.id}>
            <span>{app.job_title} — {app.company_name}</span>
            <span className={`badge ${STAGE_COLOURS[app.stage] ?? ''}`}>{app.stage}</span>
            {app.upcoming_interview && (
              <span>Interview: {new Date(app.upcoming_interview.scheduled_at).toLocaleString()}</span>
            )}
          </li>
        ))}
      </ul>
    </main>
  );
}
```

`GET /api/applicants/applications` is built in Chapter 58. This page can be stubbed with a loading state until then.

## Profile editor with résumé upload (`/dashboard/profile`)

The résumé upload is the most complex interaction:

1. User selects a PDF file
2. Client calls `POST /api/applicants/profile/resume-upload` → receives `{ uploadUrl, key }`
3. Client PUTs the file bytes to `uploadUrl` (direct to MinIO/S3)
4. Client calls `POST /api/applicants/profile/resume` with `{ key, filename }` to confirm

```tsx
// app/dashboard/profile/page.tsx (simplified Client Component for upload)
'use client';
import { useState } from 'react';

export default function ProfilePage() {
  const [uploading, setUploading] = useState(false);
  const [message, setMessage] = useState<string | null>(null);

  async function handleResumeUpload(e: React.ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    if (!file) return;

    setUploading(true);
    try {
      // Step 1: get presigned URL
      const { uploadUrl, key } = await fetch('/api/applicants/profile/resume-upload', {
        method: 'POST',
      }).then((r) => r.json());

      // Step 2: PUT directly to S3/MinIO
      await fetch(uploadUrl, {
        method: 'PUT',
        body: file,
        headers: { 'Content-Type': 'application/pdf' },
      });

      // Step 3: confirm
      await fetch('/api/applicants/profile/resume', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ key, filename: file.name }),
      });

      setMessage('Résumé uploaded successfully');
    } catch {
      setMessage('Upload failed — please try again');
    } finally {
      setUploading(false);
    }
  }

  return (
    <main>
      <h1>My Profile</h1>
      <input type="file" accept="application/pdf" onChange={handleResumeUpload} disabled={uploading} />
      {message && <p>{message}</p>}
    </main>
  );
}
```
