## 5. Scheduling for an application already at `final_interview` does not regress the stage

```bash
# First, advance an application to 'final_interview'
APP_ID_2="<id of an application at 'applied'>"

curl -s -X PATCH "http://localhost:3000/api/companies/applications/$APP_ID_2/stage" \
  -H "Authorization: Bearer $RECRUITER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"stage":"final_interview"}' | jq .stage

# Now schedule an interview — stage should NOT regress to 'interview'
curl -s -X POST "http://localhost:3000/api/companies/applications/$APP_ID_2/interview" \
  -H "Authorization: Bearer $RECRUITER_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"scheduledAt\":\"$FUTURE_DATE\",\"meetingLink\":\"https://meet.example.com/xyz\"}" \
  | jq .

psql $DATABASE_URL \
  -c "SELECT stage FROM applications WHERE id = '$APP_ID_2';"
```

Expected: `stage` remains `final_interview` after scheduling the interview.
