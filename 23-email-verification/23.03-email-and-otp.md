# Build: email transport and OTP utilities

## Install nodemailer

nodemailer is the de-facto Node.js library for sending email via SMTP. It has no runtime dependencies and works with any SMTP server, including the local Mailpit catcher used in this chapter.

```bash
npm install nodemailer
npm install --save-dev @types/nodemailer
```

## Config additions

Open `src/shared/config.ts` and add five new fields to `EnvSchema`. Place them alongside the existing JWT and database fields:

```ts
// In EnvSchema — add these fields:
SMTP_HOST:              z.string().default('localhost'),
SMTP_PORT:              z.coerce.number().int().positive().default(587),
SMTP_USER:              z.string().default(''),
SMTP_PASS:              z.string().default(''),
SMTP_FROM:              z.string().default('noreply@jobportal.local'),
OTP_EXPIRES_IN_MINUTES: z.coerce.number().int().positive().default(15),
```

The full updated schema (showing context around the new fields):

```ts
const EnvSchema = z.object({
  NODE_ENV:                      z.enum(['development', 'test', 'production']).default('development'),
  PORT:                          z.coerce.number().int().positive().default(3000),
  DATABASE_URL:                  z.string().url(),
  REDIS_URL:                     z.string().url(),
  JWT_SECRET:                    z.string().min(32),
  JWT_EXPIRES_IN:                z.string().default('15m'),
  REFRESH_TOKEN_EXPIRES_IN_DAYS: z.coerce.number().int().positive().default(7),
  SMTP_HOST:              z.string().default('localhost'),
  SMTP_PORT:              z.coerce.number().int().positive().default(587),
  SMTP_USER:              z.string().default(''),
  SMTP_PASS:              z.string().default(''),
  SMTP_FROM:              z.string().default('noreply@jobportal.local'),
  OTP_EXPIRES_IN_MINUTES: z.coerce.number().int().positive().default(15),
});
```

`z.coerce.number()` on `SMTP_PORT` converts the string value from `.env` to a number before validation. nodemailer's `port` option expects a number, not a string. Letting Zod handle the coercion keeps `config.SMTP_PORT` typed as `number` everywhere it is used.

`SMTP_USER` and `SMTP_PASS` default to empty strings rather than being required. Mailpit does not require SMTP authentication — you start it and send to it without credentials. Making these optional (with an empty-string default) means your `.env` file does not need them for local development. A production deployment would set real values.

Add to your `.env` for local development with Mailpit:

```
SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_USER=
SMTP_PASS=
SMTP_FROM=noreply@jobportal.local
```

Mailpit listens on port 1025 by default. The FROM address can be anything; Mailpit catches the email regardless.

## `src/shared/otp.ts`

Create this file. It exports two pure functions: one that generates a 6-digit OTP, and one that hashes any string with SHA-256.

```ts
// src/shared/otp.ts
import crypto from 'node:crypto';

// [100000, 1000000) — always exactly 6 digits, cryptographically random.
export function generateOtp(): string {
  return crypto.randomInt(100000, 1000000).toString();
}

// Hash a raw OTP for storage. Never store the raw value — only the hash.
export function hashOtp(otp: string): string {
  return crypto.createHash('sha256').update(otp).digest('hex');
}
```

### Why `crypto.randomInt`, not `Math.random()`

`Math.random()` is not cryptographically random — its internal state can be observed and predicted. An attacker who can observe process state could predict future OTPs. `crypto.randomInt(100000, 1000000)` uses the same CSPRNG as `crypto.randomBytes` used in Chapter 22 for refresh tokens. The OTP is a security credential; it deserves the same randomness source. The range `[100000, 1000000)` produces exactly 6 digits with no leading zeros — no padding needed.

## `src/shared/mailer.ts`

Create this file. It creates a nodemailer transport from config and exports a single function that sends the verification OTP email.

```ts
// src/shared/mailer.ts
import nodemailer from 'nodemailer';
import { config } from './config';

// Created once at module load; nodemailer reuses the connection pool.
const transporter = nodemailer.createTransport({
  host: config.SMTP_HOST,
  port: config.SMTP_PORT,
  // Use STARTTLS on port 587 / plaintext on 1025 (Mailpit). Port 465 needs secure: true.
  secure: false,
  auth:
    config.SMTP_USER && config.SMTP_PASS
      ? { user: config.SMTP_USER, pass: config.SMTP_PASS }
      : undefined,
});

// Send a verification OTP. Always pass the raw OTP — never the hash.
export async function sendVerificationEmail(to: string, otp: string): Promise<void> {
  await transporter.sendMail({
    from: config.SMTP_FROM,
    to,
    subject: 'Verify your email address',
    text: [
      'Welcome to the job portal.',
      '',
      'Your verification code is:',
      '',
      `    ${otp}`,
      '',
      'Enter this code in the app to activate your account.',
      'The code expires in 15 minutes.',
      '',
      'If you did not create an account, you can ignore this email.',
    ].join('\n'),
  });
}
```

### Why the transport is created once at module load

nodemailer's `createTransport` does not open a network connection immediately — it configures the options object. The connection is opened on the first `sendMail` call and then pooled. Creating the transporter at module load time is standard practice: it keeps configuration in one place, and any misconfiguration (wrong host, invalid port) fails early rather than at the first send attempt at runtime.

### Why `auth` is conditionally set

Mailpit does not require SMTP authentication. Passing `auth: undefined` tells nodemailer to skip the AUTH handshake. Sending `auth: { user: '', pass: '' }` with empty strings would cause some SMTP servers to reject the connection. The conditional `config.SMTP_USER && config.SMTP_PASS ? ... : undefined` handles both cases cleanly without requiring a separate boolean config field.

### Why the OTP appears in the text body, not a link

The OTP is a code the user types. It does not need to be embedded in a URL. A URL would require a frontend route to receive it (`/verify?token=123456`), a page to display a success or failure state, and CORS handling if the frontend is on a different domain. The OTP approach pushes all of that complexity to a later chapter when the React/Next.js frontend is built. For now, `POST /auth/verify-email` is the only consumer of the OTP.

## Mailpit quick reference

| What                  | Value                       |
|-----------------------|-----------------------------|
| SMTP port             | 1025                        |
| Web UI                | http://localhost:4025       |
| Auth required         | No                          |
| Emails delivered      | Never — caught locally only |

When `sendVerificationEmail` runs during local development, open `http://localhost:4025` in your browser. The email will appear in the inbox within a second or two. Click it to read the body and retrieve the OTP.

Mailpit does not persist emails across restarts. If you restart Mailpit, the inbox is empty.
