# Chapter 45 — Cache Invalidation

## What you will build

Invalidate `'jobs:public:page1'` whenever a job is published, closed, or newly created as open. The invalidation happens inside the service, after the database write succeeds.

## Learning goals

- Understand why cache invalidation must happen after the DB write, not before
- Implement the correct invalidation pattern using `redis.del`
- Understand and demonstrate a stale-read bug caused by missing invalidation
- Know where to add future invalidation hooks (company status changes)

## Prerequisites

- Chapter 44: cache in place, `'jobs:public:page1'` key exists
- `redis` client from `src/shared/redis.ts`

## Files you will modify

```
src/modules/jobs/jobsService.ts    ← add invalidation calls after publish/close
```

## The rule

Cache invalidation must happen **after** the DB write succeeds. If the write fails (database error, constraint violation), the invalidation must not happen — there is nothing new to show. If invalidation happens before the write, a concurrent request gets a cache miss, queries the DB, reads the old value, and re-caches the old value. The new state is never served.

```
WRONG:
  await redis.del('jobs:public:page1')  ← cache cleared
  await db.query('UPDATE jobs ...')      ← write fails: DB error
  → cache is now empty, next miss re-reads old data from DB, re-caches old data

CORRECT:
  await db.query('UPDATE jobs ...')      ← write succeeds
  await redis.del('jobs:public:page1')  ← cache cleared only on success
  → next request gets a cache miss, reads fresh data from DB
```

## The stale-read bug

Without invalidation, the sequence is:

1. Job is published (`status = 'open'` written to DB)
2. `'jobs:public:page1'` still holds the old result (job not present)
3. Applicant requests the board — gets cached response — job is invisible
4. 60 seconds pass — TTL expires — next request hits DB — job appears

With invalidation:

1. Job is published
2. `redis.del('jobs:public:page1')` runs
3. Next request gets a cache miss — hits DB — job appears immediately
