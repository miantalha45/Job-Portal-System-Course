# 68.02 — Scheduled Jobs (Walkthrough)

## How BullMQ repeatable jobs work

When you call `queue.add('job-name', payload, { repeat: { pattern: '0 0 * * *' } })`, BullMQ:

1. Stores the repeatable job configuration in Redis under a key like
   `bull:jobs:repeat:<hash>`
2. Calculates the next run time based on the cron pattern
3. Adds a delayed job entry that fires at that time
4. After the job runs, BullMQ automatically schedules the next occurrence

The job itself is a normal BullMQ job — it goes through the same worker dispatch as any other
job. The only difference is that BullMQ schedules it automatically instead of your code calling
`queue.add` each time.

## Building it step by step

### Step 1 — Create cleanupExpiredOtps.ts

The handler is a simple DELETE query:

```sql
DELETE FROM email_verifications WHERE expires_at < NOW()
```

`pg`'s `db.query` returns a result object with `rowCount` — the number of rows affected by
the DELETE. Log it so you can see the cleanup activity in your worker output.

### Step 2 — Create cleanupExpiredTokens.ts

Same pattern:

```sql
DELETE FROM refresh_tokens WHERE expires_at < NOW()
```

### Step 3 — Register repeatable jobs in worker.ts

The registration is done at startup, before the Worker instance begins polling. Use a separate
Queue instance (`schedulerQueue`) just for registration — close it when done.

```ts
const schedulerQueue = new Queue('jobs', {
  connection: { url: config.REDIS_URL },
});

await schedulerQueue.add('cleanup-expired-otps', {}, {
  repeat: { pattern: '0 0 * * *' },
});

await schedulerQueue.add('cleanup-expired-refresh-tokens', {}, {
  repeat: { pattern: '0 1 * * *' },
});

const jobs = await schedulerQueue.getRepeatableJobs();
console.log('[worker] Repeatable jobs:', jobs.map(j => `${j.name} → ${j.pattern}`));
await schedulerQueue.close();
```

### Step 4 — Add handlers to the worker switch

Both handlers take no arguments from `job.data` — they query the database directly:

```ts
case 'cleanup-expired-otps': {
  await cleanupExpiredOtps();
  break;
}
case 'cleanup-expired-refresh-tokens': {
  await cleanupExpiredTokens();
  break;
}
```

### Step 5 — Verify the repeatable jobs are registered

After starting the worker:

```bash
npx ts-node -e "
import { Queue } from 'bullmq';
import config from './src/shared/config';
(async () => {
  const q = new Queue('jobs', { connection: { url: config.REDIS_URL } });
  const jobs = await q.getRepeatableJobs();
  console.log(JSON.stringify(jobs.map(j => ({ name: j.name, pattern: j.pattern })), null, 2));
  await q.close();
})();
"
```

Expected output:
```json
[
  { "name": "cleanup-expired-otps", "pattern": "0 0 * * *" },
  { "name": "cleanup-expired-refresh-tokens", "pattern": "0 1 * * *" }
]
```

## Testing without waiting for midnight

To test the cleanup handlers without waiting for the cron trigger, enqueue them manually:

```bash
npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  await queue.add('cleanup-expired-otps', {});
  await queue.add('cleanup-expired-refresh-tokens', {});
  await queue.close();
})();
"
```

Watch the worker log:
```
[worker] Processing job cleanup-expired-otps
[cleanup] Deleted 3 expired OTP rows
[worker] Job completed: cleanup-expired-otps
```

And verify in PostgreSQL:
```bash
psql $DATABASE_URL -c \
  "SELECT count(*) FROM email_verifications WHERE expires_at < NOW();"
# Expected: 0
```

## Idempotency of the cleanup jobs

Both DELETE queries are naturally idempotent:
- Running the DELETE twice produces the same result (all expired rows are gone after either run)
- The second run deletes 0 rows and completes successfully
- `rowCount` will be 0 on the second run — that is correct, not an error

No `ON CONFLICT` needed because DELETE has no conflict condition.

---

## What happens on worker restart

Repeatable jobs registered in Redis survive worker restarts. On restart, calling
`queue.add` with the same repeat configuration is idempotent — BullMQ updates the existing
repeatable entry rather than creating a duplicate. The next run time is preserved.

If you want to stop a repeatable job, call:

```ts
await queue.removeRepeatableByKey(job.key);
// or
await queue.removeRepeatable('cleanup-expired-otps', { pattern: '0 0 * * *' });
```
