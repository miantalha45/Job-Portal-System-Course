# Chapter 68 — Definition of Done

## Verifiable checklist

```bash
# 1. TypeScript compiles with zero errors
npx tsc --noEmit

# 2. Handler files exist
ls src/worker/handlers/cleanupExpiredOtps.ts
ls src/worker/handlers/cleanupExpiredTokens.ts
# Expected: both files listed

# 3. Start the worker
npm run worker
# Expected log lines:
# [worker] Repeatable jobs registered: [ 'cleanup-expired-otps', 'cleanup-expired-refresh-tokens' ]
# [worker] Worker started and listening for jobs...

# 4. Confirm repeatable jobs are in Redis
npx ts-node -e "
import { Queue } from 'bullmq';
import config from './src/shared/config';
(async () => {
  const q = new Queue('jobs', { connection: { url: config.REDIS_URL } });
  const jobs = await q.getRepeatableJobs();
  console.log('Count:', jobs.length);
  jobs.forEach(j => console.log(j.name, j.pattern));
  await q.close();
})();
"
# Expected:
# Count: 2
# cleanup-expired-otps 0 0 * * *
# cleanup-expired-refresh-tokens 0 1 * * *

# 5. Insert some expired OTP rows for testing
psql $DATABASE_URL -c "
INSERT INTO email_verifications (user_id, token, expires_at)
SELECT id, 'test-token-' || id, NOW() - INTERVAL '1 hour'
FROM users LIMIT 3;"

# 6. Manually trigger the OTP cleanup job
npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  await queue.add('cleanup-expired-otps', {});
  console.log('Job enqueued');
  await queue.close();
})();
"

# 7. Confirm the expired rows were deleted
psql $DATABASE_URL -c \
  "SELECT count(*) FROM email_verifications WHERE expires_at < NOW();"
# Expected: count = 0

# 8. Insert some expired refresh tokens and test cleanup
psql $DATABASE_URL -c "
INSERT INTO refresh_tokens (user_id, token, expires_at)
SELECT id, 'test-rt-' || id, NOW() - INTERVAL '1 hour'
FROM users LIMIT 2;"

npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  await queue.add('cleanup-expired-refresh-tokens', {});
  await queue.close();
})();
"

psql $DATABASE_URL -c \
  "SELECT count(*) FROM refresh_tokens WHERE expires_at < NOW();"
# Expected: count = 0

# 9. Confirm no process.env in handler files
grep 'process\.env' src/worker/handlers/cleanupExpiredOtps.ts
grep 'process\.env' src/worker/handlers/cleanupExpiredTokens.ts
# Expected: no output from either command
```

## Quiz

1. Repeatable jobs are registered by calling `queue.add` with `{ repeat: { pattern } }` every
   time the worker starts. If the worker restarts 10 times in a day, does this create 10
   separate scheduled jobs? Explain what BullMQ does with repeated registration of the same
   repeatable job.

2. The cron patterns are hardcoded in `worker.ts` rather than read from `config.ts`. A developer
   argues they should be in environment variables so operations teams can change the schedule
   without redeploying. What is the argument for hardcoding them? What is the argument for
   making them configurable? Which side would you take and why?

3. A cleanup job runs at midnight and deletes 10,000 rows from `email_verifications`. The
   DELETE takes 8 seconds. The next cleanup run is scheduled for the following midnight.
   Is there a risk of the job running again before it completes? How does BullMQ's job locking
   mechanism prevent this, and what is the lock expiry you would need to watch?
