# Chapter 30 — Prerequisites and framing

## What you need in place

**Chapter 28** — `getRecruiterCompany(userId)` resolves a recruiter's `company_id` from the verified JWT. This is the isolation mechanism.

**Chapter 29** — `assertJobOwnership(jobId, companyId)` throws `NotFoundError` when a job does not belong to the caller's company. `GET /api/jobs/:id` uses this check.

**Database seed data** — two companies with at least one recruiter each, and at least one job per company. The attack test requires jobs from two different companies to be present.

**Admin account** — a user with `role: 'admin'` in the database, able to log in and receive a valid JWT.

Run `npx tsc --noEmit` before you begin.

---

## What this chapter builds

This chapter does not add new application code. It proves that the isolation built in Chapters 28 and 29 works correctly through a structured manual test sequence — an attack test using curl.

The attack test simulates an adversarial recruiter attempting to access another company's job. It documents the expected outcome (404) and explains why any other response code would indicate a broken isolation boundary.

It also documents the admin exception: an admin calling the same job endpoint returns data, not 404. This is the only sanctioned path through the isolation boundary and must be explicitly demonstrated to show it is deliberate — not an accident.

The chapter closes by restating the isolation rule as a code comment, making it part of the codebase record rather than only a chapter explanation.

## The admin route for this test

The admin exception requires a route that the admin can call to access a job regardless of which company owns it. Add a simple admin job-lookup route in `src/modules/admin/admin.routes.ts`:

```ts
router.get('/jobs/:id', async (req, res, next) => {
  try {
    const result = await db.query(
      `SELECT id, title, company_id, status FROM jobs WHERE id = $1`,
      [req.params.id],
    );

    if (result.rows.length === 0) {
      return next(new NotFoundError('Job not found'));
    }

    res.json(result.rows[0]);
  } catch (err) {
    next(err);
  }
});
```

Note: there is no `WHERE company_id = ...` clause. The admin query is deliberately unscoped. The isolation boundary is enforced by `requireRole('admin')`, not by a company filter.
