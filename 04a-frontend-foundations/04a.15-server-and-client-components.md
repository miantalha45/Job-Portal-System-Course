# Choose Server and Client Components deliberately

Use a Server Component by default for pages that fetch and display data: public job lists, dashboard tables, and application history. Use a Client Component only when browser interactivity is required: controlled form inputs, file selection, a confirm dialog, or a button click that changes local state.

Keep client boundaries small. A whole dashboard page does not need `'use client'` because one button is interactive.

For each page you add, write one sentence in the learning log explaining why it is server, client, or a mix.
