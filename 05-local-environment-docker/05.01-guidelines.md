# Guidelines for this chapter

A quick frame before you start. This is a setup chapter — read it, then build.

**Revise coming in.** You need only the basics: you can move around a terminal and run commands. You do **not** need any prior Docker experience — it's taught here from scratch, with the mental model first and the commands second. If you've never opened a `docker-compose.yml`, you're in the right place.

**Keep it yours.** The services are standard (Postgres + Redis), so just make the repo yours — the database name, the user, the local password, and your commit messages. The one thing that isn't optional is the *shape* — services declared in Compose, images pinned, the database on a named volume.

**Daily working guidelines.** Make a clean commit by end of day (the `docker-compose.yml`, not the data), and check that nothing secret slipped past `.gitignore` — your `.env` carries a database password and must stay out of Git. And carry one question as you build, because it's the trap this chapter is really about: **if you skip the named volume, what happens to your data — and every seed row and test record you create — the first time you rebuild the container?** Hold that thought; it's why the volume is mandatory, not optional.
