# Bring the services up

Your app boots but talks to nothing. Let's give it services. We'll start with the simplest thing that works, then harden it in the next file.

## Install Docker

Install **Docker Desktop** (Mac/Windows) or **Docker Engine** (Linux) from the official guide — search *"install Docker Desktop docs.docker.com"* and follow your platform's instructions.

**Verify:**

```
docker --version          # prints a version
docker compose version    # prints a version
```

If both print versions, you're ready. (If `docker compose` isn't found, your install is older — modern Docker ships Compose built in; check the install guide.)

## The minimal `docker-compose.yml`

Create `docker-compose.yml` at your project root. Start with the *minimum* to get Postgres and Redis up — don't reach for advanced options yet.

```yaml
# docker-compose.yml — the minimal version (we harden it in 05.04)
services:
  postgres:
    image: postgres                 # official Postgres image (we pin the version next)
    environment:
      POSTGRES_USER: portal         # the DB user…
      POSTGRES_PASSWORD: localdevpw # …its password — fine in the file for LOCAL dev only
      POSTGRES_DB: jobportal        # the database created on first run
    ports:
      - "5432:5432"                 # map container port → laptop, so the app can connect

  redis:
    image: redis                    # official Redis image
    ports:
      - "6379:6379"
```

## Start them and check

Bring both up in the background, then confirm — never assume.

```
docker compose up -d        # start both, detached
docker compose ps           # both should show as running
```

✅ **Do** start with this minimal file and confirm it runs before adding anything.
❌ **Don't** copy the hardened version yet — get a green `ps` first, then climb.

**Verify:** `docker compose ps` lists both `postgres` and `redis` as running (state `Up`/`running`). If so, you have a working local environment — now let's make it robust.
