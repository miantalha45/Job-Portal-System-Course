# Build it — git & daily habits

The app boots. Before you call it done, lock in the working rhythm from the intro — starting for real today.

## .gitignore first

Add a `.gitignore` *before* your first commit, so the things that must never be committed never are:

```gitignore
# .gitignore
node_modules/      # dependencies — reinstalled from package.json, never committed
dist/              # build output — regenerated by `npm run build`
.env               # secrets — never, ever in Git
.env.*.local       # local env overrides
```

`node_modules/` and `dist/` are *generated* — committing them bloats the repo and causes merge noise. `.env` will hold secrets (Chapter 6); a secret in Git history is a secret leaked, so block it now, before there's anything to leak.

## git init + first commit

```bash
git init
git add -A
git commit -m "chore: bootstrap TypeScript project skeleton"
```

From here, you commit every day — that's the habit.

## Optional: ESLint + Prettier

Not required, but adding **ESLint + Prettier** keeps dozens of chapters of code consistently formatted and catches a class of mistakes before you run — a one-line install when you want it.

## Make it yours

A clean first build-in-public note: *"How I structured my job-portal backend — and the trade-off I chose."* Short and opinionated, with your folder sketch and the "adding a feature" comparison from 04.04. Shipping the reasoning out loud is how you'll remember it at the viva.

✅ **Do** add `.gitignore` *before* the first commit, so generated/secret files were never tracked.
❌ **Don't** `git add` `node_modules/` or `dist/` — if they slip in, untrack them before committing.

**Verify:** run `git status`. It should be clean of `node_modules/`, `dist/`, and `.env` — those don't appear as tracked or staged. `git log` shows your first commit.
