# Build it — a skeleton that boots

You have the structure, the compiler, and the scripts. Now make the smallest possible app that actually runs — and notice the entry point splits into *two* files on purpose.

## The app.ts / server.ts split

- **`src/app.ts`** *builds and wires* the framework instance — installs your framework, registers any baseline middleware, and (later) mounts your module routes — then **returns** it. It does **not** start listening on a port.
- **`src/server.ts`** imports that app and **starts it listening**. It's the only file that actually "runs the server."

Write these two files yourself — the logic is yours. To keep this chapter buildable, here's only the *contract*, not the code:

- `app.ts` exports something like a `buildApp()` that returns the wired framework instance.
- `server.ts` imports it, calls it, and tells the instance to listen.
- For now a single placeholder route (e.g. `GET /` returning `"ok"` or a JSON `{}`) is all you need to prove it's alive.

The route-registration *shape* you'll repeat per module looks roughly like this one line — illustration only, not the file to copy:

```
app.register(jobsRoutes)   // (or app.use('/jobs', jobsRouter) — whatever your framework uses)
```

## Why split them — testability

Why bother with two files? **Testability.** In `../30-isolation-attack-test/` you'll fire requests at the fully-wired app to prove one Company can't read another's data — and you'll want to do that *without* opening a real network port (faster, no port clashes, runs anywhere). That's only possible if "build the app" and "start listening" are *separate* steps: the test imports `buildApp()` and injects fake requests; production runs `server.ts`. Setting it up now costs nothing and saves a refactor later.

## Run it

Your goal for this chapter is just to run the dev server and watch the app come up and stay up:

```bash
npm run dev
```

✅ **Do** keep all listening logic in `server.ts` and all wiring in `app.ts`.
✅ **Do** keep it minimal — one placeholder response proves the skeleton boots.
❌ **Don't** add a real `/health` endpoint yet — that's `../07-health-check/`.
❌ **Don't** read the port from environment config yet — reading config is `../06-config-and-secrets/`. Hard-code a port for now; you'll replace it properly there.

**Verify:** `npm run dev` starts and *stays running* (it doesn't exit). Hit the placeholder route in a browser or with `curl http://localhost:<port>/` and get your placeholder response back. Save a file and watch tsx reload. The app exists and boots.
