# Guidelines for this chapter

A quick frame before you start scaffolding — read it, then build.

**Revise coming in.** This chapter assumes only the basics: you can move around a terminal and run `npm`/`pnpm`/`yarn`, and you've seen your framework's hello-world (the three-line "server responds on a port" example from its docs). Nothing here is something the course teaches from scratch — if any of that feels rusty, a five-minute skim of your framework's quickstart is enough.

**Keep it yours.** It's *your* repo — the file names inside each module, the commit messages, the project name are yours. The one thing that isn't optional is the *shape* (feature/module-based), which the rest of the course assumes.

**Daily working guidelines.** You write real code today, so the habits start for real: make a clean commit by end of day, and check that nothing secret or generated slipped past `.gitignore` (no `node_modules/`, no `dist/`). And carry one question as you build — it's the cost this chapter is really about: **the folder shape you pick now, every later chapter assumes — what breaks if you decide to re-organise it in week 3, with a dozen modules already wired together?** Hold that thought; it's why this chapter *mandates* a structure instead of leaving it open.
