# Build it — initialise the project

Start an empty Node project and add TypeScript plus a dev runner. The package manager is your call — npm, pnpm, or yarn — but **pick one and stick to it** (mixing lockfiles is a mess). The steps are the same; npm is shown:

```bash
# inside a new, empty project folder
npm init -y                                   # creates package.json
npm install --save-dev typescript tsx @types/node
npx tsc --init                                # creates tsconfig.json
```

What each piece is, so nothing is magic:

- **typescript** — the compiler (`tsc`) that type-checks your code and turns it into plain JavaScript.
- **tsx** — runs TypeScript files *directly*, with hot reload, so during development you don't have to compile-then-run on every change.
- **@types/node** — the type definitions for Node's built-ins, so TypeScript understands `process`, `path`, `Buffer`, and friends.

That's the whole toolchain for now. (Your web framework and its types come later, when you wire the skeleton — keep this step to the language tooling.)

✅ **Do** commit to one package manager and one lockfile.
✅ **Do** keep these as `--save-dev` — they're build/dev tooling, not runtime dependencies.
❌ **Don't** clone an "ultimate TypeScript starter" off the internet. You'd inherit fifteen folders and a dozen flags you didn't choose and can't explain — exactly the trap Chapter 3 warned about. Build the small thing you understand.

**Verify:** `package.json` and `tsconfig.json` both exist in your project root, and `node_modules/` was created. That's the empty shell — next, give it a shape.
