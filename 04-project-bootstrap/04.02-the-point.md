# The point of this chapter

You've decided *what* you're building with. Now you create the thing those tools live in: the application skeleton.

**What you'll have by the end:** a TypeScript project that boots with a *single command*, configured strictly, and laid out so it won't collapse as the job portal grows from one feature to a dozen. One script brings the app up and keeps it alive — a placeholder response is plenty — and the folders are ready for everything the next modules add.

**Why bootstrap before the database.** The app doesn't need a database to *exist*. And it's far easier to stand up Postgres and Redis (next chapter) once there's an app sitting there waiting to talk to them, than to wire services into nothing. So: skeleton first, services second.

**The one decision that actually matters here** is how you lay out your code. Everything else in this chapter is mechanical — install these, set these flags, add these scripts. But the folder structure is a choice you'll either thank or curse yourself for across the rest of the course, so we'll take that one slowly and decide it deliberately.

This chapter is foundational, not flashy — nothing a user sees gets built. That's fine. A clean skeleton now is what lets every later chapter line up instead of fight you.
