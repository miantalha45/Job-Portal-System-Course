# Definition of Done

Things you can **see or run** — and the gate to Chapter 5. Tick every box before you continue:

- [ ] `npm run dev` starts the app and it *stays up*, serving a placeholder response at `/`
- [ ] `tsconfig.json` has **`"strict": true`**, with `rootDir: src` and `outDir: dist`
- [ ] `npm run build` compiles `src/` into `dist/`, and `npm start` runs the compiled output
- [ ] `dev`, `build`, `start`, and `typecheck` scripts exist, and you can explain how `dev` and `start` differ
- [ ] The project uses **feature/module-based** structure (**required**): `src/modules/{auth, companies, jobs, applications, applicants, admin}/` each with its four files, plus `src/shared/` placeholders
- [ ] `app.ts` (wiring) is split from `server.ts` (listening)
- [ ] `git init` done, a **first commit** made, and `.gitignore` excludes `node_modules/`, `dist/`, and `.env`
- [ ] No secrets committed (there shouldn't be any yet — keep it that way)

> **✍️ Log it (mandatory).** In `learning-log/04-project-bootstrap.md`, answer in your own words: (1) Which folder structure did you choose, and *why* — walk through "adding a feature" in both styles to justify it. (2) Why keep TypeScript `strict` mode on — what does it catch, and *when*? (3) What's the difference between how your app runs in development (`dev`) versus production (`start`)? (4) Why split `app.ts` from `server.ts` — what does it buy you in Chapter 30? Commit it.
