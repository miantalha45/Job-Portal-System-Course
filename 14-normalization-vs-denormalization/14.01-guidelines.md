# Guidelines — Chapter 14

## Before you start

You need the schema from chapters 8–10: the `jobs`, `applicants`, and `applications` tables with their JSONB columns. The decisions this chapter examines are already in your learning log — this chapter gives them a name and a frame for every schema decision that follows.

No code is written in this chapter. The output is a sharpened mental model and two learning-log entries.

## Rethink impact

> The `jobs` table stores `{ "seniority": "mid", "tech_stack": ["Go", "PostgreSQL"] }` in the `attributes` JSONB column. A feature request arrives: add a filter on the public job board so users can browse jobs by seniority level. PostgreSQL can index a JSONB path expression — but what makes that harder to maintain than indexing a real column? And at what point does the right answer change from "use a JSONB expression index" to "promote this to a real column"?
