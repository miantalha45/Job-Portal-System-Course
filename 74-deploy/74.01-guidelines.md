# Chapter 74 — Deploy: App + Worker, Secrets, HTTPS

## What you will build

A production-like Docker Compose setup with separate containers for the API, the worker,
PostgreSQL, and Redis. An nginx reverse proxy handles TLS termination. Migrations run as a
one-off task before the API starts.

## Learning goals

- Write a multi-stage Dockerfile for Node.js + TypeScript
- Understand the difference between build-time deps and runtime deps
- Run database migrations as a pre-start step, not inside the application
- Configure HTTPS via nginx as a reverse proxy

## Prerequisites

- Chapter 72: graceful shutdown (SIGTERM handling)
- Chapters 63–68: worker process
- All migrations in `migrations/` directory

### Dockerfile (API)

```dockerfile
# ---- Build stage ----
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci                        # install all deps (including devDeps for tsc)
COPY . .
RUN npm run build                 # tsc → dist/

# ---- Production stage ----
FROM node:20-alpine AS runner
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev             # production deps only
COPY --from=builder /app/dist ./dist
COPY migrations ./migrations      # migrations are needed for the one-off task

ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

### Dockerfile.worker

FROM node:20-alpine AS builder

### docker-compose.prod.yml

```yaml
version: '3.9'

services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: jobportal
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 5

  migrate:
    image: postgres:16-alpine
    environment:
      PGPASSWORD: ${POSTGRES_PASSWORD}
    command: >
      sh -c "for f in /migrations/*.sql; do
               psql -h postgres -U postgres -d jobportal -f $$f;
             done"
    volumes:
      - ./migrations:/migrations
    depends_on:
      postgres:
        condition: service_healthy

  api:
    build:
      context: .
      dockerfile: Dockerfile
    env_file: .env.production
    ports:
      - "3000:3000"
    depends_on:
      migrate:
        condition: service_completed_successfully
      redis:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s

  worker:
    build:
      context: .
      dockerfile: Dockerfile.worker
    env_file: .env.production
    depends_on:
      migrate:
        condition: service_completed_successfully
      redis:
        condition: service_healthy

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/certs:/etc/nginx/certs:ro
    depends_on:
      - api

volumes:
  pgdata:
  redisdata:
```

### nginx/nginx.conf

```nginx
events {}

http {
  upstream api {
    server api:3000;
  }

  server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
  }

  server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;

    location / {
      proxy_pass         http://api;
      proxy_http_version 1.1;
      proxy_set_header   Upgrade $http_upgrade;
      proxy_set_header   Connection 'upgrade';
      proxy_set_header   Host $host;
      proxy_set_header   X-Real-IP $remote_addr;
      proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_set_header   X-Forwarded-Proto $scheme;
    }
  }
}
```

## Secrets management

Secrets are injected at runtime via environment variables. Never bake secrets into the image:

```bash
# Bad: in Dockerfile
ENV DATABASE_URL=postgresql://...

# Good: at runtime
docker run --env-file .env.production my-api-image
```

The `.env.production` file is NOT committed to git. It is created on the production server
by the operations team or a secrets manager (AWS Secrets Manager, Vault, etc.).

## Running migrations as a one-off task

The `migrate` service runs once and exits. The `api` service depends on it with
`condition: service_completed_successfully` — it only starts if migrations exit with code 0.

Alternatively, without Compose:

```bash
# Build the image first
docker build -t jobportal-api .

# Run migrations
docker run --rm \
  --network prod-net \
  -e DATABASE_URL=$DATABASE_URL \
  postgres:16-alpine \
  psql $DATABASE_URL -f /migrations/001_init.sql
```

---

## No `process.env` in application modules

The Docker Compose `env_file: .env.production` injects environment variables into the
container at startup. The Express API reads them only through `config.ts`. No application
module reads `process.env` directly.
