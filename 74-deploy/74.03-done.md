# Chapter 74 — Definition of Done

## Verifiable checklist

```bash
# 1. TypeScript compiles with zero errors (local)
npx tsc --noEmit

# 2. Dockerfile exists and builds without errors
docker build -t jobportal-api:test -f Dockerfile .
# Expected: BUILD SUCCESSFUL, no errors

# 3. Dockerfile.worker exists and builds without errors
docker build -t jobportal-worker:test -f Dockerfile.worker .
# Expected: BUILD SUCCESSFUL, no errors

# 4. Final API image contains only dist/ and production node_modules (no src/)
docker run --rm jobportal-api:test ls /app
# Expected: dist  node_modules  package.json  package-lock.json  migrations
# NOT expected: src  tsconfig.json

# 5. TypeScript source is NOT in the production image
docker run --rm jobportal-api:test ls /app/src 2>&1
# Expected: "ls: /app/src: No such file or directory" or similar error

# 6. devDependencies are NOT in the production image
docker run --rm jobportal-api:test node -e "require('typescript')" 2>&1
# Expected: "Cannot find module 'typescript'" (not in production deps)

# 7. docker-compose.prod.yml is valid
docker compose -f docker-compose.prod.yml config 2>&1 | head -5
# Expected: no errors, shows the merged config

# 8. Start the full stack (requires .env.production to exist)
cp .env .env.production   # use dev values for local test
docker compose -f docker-compose.prod.yml up --build -d

# Wait for services to be healthy
sleep 15

# 9. API health check via port 3000 (before nginx)
curl -s http://localhost:3000/health | jq '.status'
# Expected: "ok"

# 10. API readiness check
curl -s http://localhost:3000/ready | jq '.'
# Expected: { "status": "ok", "checks": { "db": "ok", "redis": "ok" } }

# 11. Migrations ran (verify tables exist)
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U postgres -d jobportal -c "\dt"
# Expected: all tables (users, companies, jobs, applications, etc.) listed

# 12. Worker is running
docker compose -f docker-compose.prod.yml ps worker
# Expected: worker is in "running" state

# 13. X-Content-Type-Options header present (helmet working in container)
curl -sI http://localhost:3000/health | grep 'X-Content-Type'
# Expected: X-Content-Type-Options: nosniff

# 14. Stop the stack
docker compose -f docker-compose.prod.yml down

# 15. Confirm .env.production is in .gitignore
grep '.env.production' .gitignore
# Expected: .env.production line present
```

## Log-it

1. Compare the image size of the single-stage approach vs the multi-stage approach. Run:
   ```bash
   docker build --target builder -t jobportal-single . && docker images jobportal-single
   docker build -t jobportal-multi . && docker images jobportal-multi
   ```
   Record both sizes. Write down why the smaller image matters in production (startup time,
   registry bandwidth, attack surface).

2. The `migrate` service runs SQL files in alphabetical order. What would happen if a developer
   named a new migration `009_add_column.sql` but a file `010_something.sql` already exists that
   depends on the new column? Write down the failure mode and explain how the naming convention
   prevents it.

## Quiz

1. The Dockerfile uses `npm ci --omit=dev` in the runner stage instead of `npm install`. What
   is the difference between `npm ci` and `npm install`, and why is `npm ci` the correct choice
   for a Docker build?

2. The `migrate` service in docker-compose.prod.yml uses `condition: service_completed_successfully`.
   What happens if a migration SQL file has a syntax error — does the API start? What is the
   exit code of the `migrate` service in that case, and how does Docker Compose use it?

3. The nginx config terminates TLS and proxies plain HTTP to the API. The API sets
   `Strict-Transport-Security` headers via Helmet. When a browser requests the API directly
   on port 3000 (bypassing nginx), `Strict-Transport-Security` is set on an HTTP response.
   Is this a problem? What does HSTS do with a header received over plain HTTP?
