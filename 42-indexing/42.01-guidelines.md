## The migration file

Create `migrations/009_add_indexes.sql` and apply it:

```bash
psql $DATABASE_URL -f migrations/009_add_indexes.sql
```

## Why migrations for indexes

Indexes are schema changes. They belong in a migration file for the same reason column changes do: they must be reproducible, version-controlled, and applied in order across all environments (local, staging, production). An index applied manually to the production database that is not in source control is a schema drift — the next developer who clones the repo will not have it.

## Notes

- `CREATE INDEX CONCURRENTLY` is the production-safe way to add indexes to a live table. It builds the index without holding a lock that blocks writes. In this course, we use plain `CREATE INDEX` because we are in development; the migration notes when `CONCURRENTLY` would be used in production.
- PostgreSQL may choose not to use an index if the table is small enough that a sequential scan is cheaper. The EXPLAIN examples use realistic row counts.
