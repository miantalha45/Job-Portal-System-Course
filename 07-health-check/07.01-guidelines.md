# Guidelines — Chapter 7

## Before you start

You need two things from earlier chapters:

- The project skeleton from [Chapter 4](../04-project-bootstrap/) — specifically `src/app.ts` and `src/server.ts` exist and `npm run dev` starts the server.
- The config module from [Chapter 6](../06-config-and-secrets/) — `config.PORT` is available in `src/shared/config.ts`.

No new packages needed. This chapter adds one route.

## Keep it yours

This is a structural chapter. The route has one name (`/health`) and one job — you're wiring it to the process you already bootstrapped.

## Rethink impact

> You push a fix at midnight. The deployment succeeds, the container starts, and the load balancer immediately marks the new instance healthy and starts routing traffic. But the Node process hasn't finished binding to the port yet — the first thirty requests hit a connection-refused error before the server is ready.
>
> Or the reverse: a bad migration left the app in a crash-restart loop. The orchestrator keeps sending traffic because nothing told it anything was wrong.
>
> What HTTP endpoint would have prevented both?

Every production service needs a health check before its first external consumer. Building it now — at the start of the project — means it's never missing, never retrofitted.
