# Verifying the endpoint

## Start the server

```bash
npm run dev
```

The startup log should confirm the port — something like `Server listening on http://0.0.0.0:3000`. The actual port comes from `config.PORT`, which you set in `.env` in Chapter 6. Use that value in every command below (shown as `<PORT>`).

## Probe it

```bash
curl -s http://localhost:<PORT>/health | jq .
```

Expected response — HTTP 200, body:

```json
{
  "status": "ok",
  "uptime": 4,
  "timestamp": "2025-09-01T08:00:04.217Z"
}
```

The `uptime` and `timestamp` values change each call; that's correct. If `jq` isn't installed, drop the pipe — the raw JSON is readable without it.

## Check the status code explicitly

Monitoring tools key off the HTTP status code, not just the body. Confirm the code:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:<PORT>/health
```

Expected output: `200`.

## Two things to confirm

**1. A route that doesn't exist returns a non-200 code.**

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/nonexistent
```

This should return `404` — confirming the 200 from `/health` is specific to that route, not a framework default.

**2. The app still starts cleanly.**

Run `npm run dev`, check the output for errors, and confirm no existing behaviour regressed. The health route should add to the app, not break it.
