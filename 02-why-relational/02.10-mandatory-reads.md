# 📖 Mandatory reads

Read these before the data-model module (Chapter 8) — the next chapters assume you hold these ideas in your head, not just the conclusion above. Each is named with a search term, never an invented link; find the current official source.

- **ACID & database transactions** — read the "Transactions" introduction in the **PostgreSQL documentation** (search: *"PostgreSQL documentation transactions"*). *Required because: the application submission (Chapter 52) is one big transaction; you need the mental model now, not when you're mid-build.*
- **SQL vs NoSQL — when to use which** — read one balanced, non-marketing comparison (search: *"SQL vs NoSQL when to use it depends"*). *Required because: at the viva you must be able to argue both sides, including the honest case for the document model — not just the one you picked.*
- **Database normalization (1NF → 3NF), a primer** — a short explainer (search: *"database normalization 1NF 2NF 3NF explained"*). *Required because: the data-model module designs the schema around these forms, and Week 3 deliberately bends them for speed — you can't knowingly bend a rule you don't know.*

> **Interesting to read.** Shopify — one of the largest commerce platforms in the world — runs its core transactional data on **sharded MySQL**: relational at the heart, precisely for the correctness guarantees high-stakes data demands. Search *"Shopify MySQL sharding"* for how they scaled a relational core to enormous size. It's a good antidote to the myth that "relational doesn't scale," and it's exactly the reasoning behind choosing relational for your hiring data.
