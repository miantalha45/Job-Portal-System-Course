# Chapter 59 — Admin Moderation: Verifying & Suspending Companies

## What you will build

Three admin endpoints that let a super-admin list companies by status, verify a pending company,
and suspend a verified company. Suspension automatically closes all of that company's open jobs
and purges the public job-board cache.

## Learning goals

- Add write actions (PATCH) to the admin router without giving any company member access
- Understand compound side effects: one HTTP call triggers two SQL writes + a cache deletion
- Return meaningful 409 Conflict when an action would have no effect

## Prerequisites

- Chapter 26: `requireRole` middleware in place
- Chapter 44–45: Redis cache and invalidation pattern
- `companies` table with `status CHECK('pending','verified','suspended')`
- `jobs` table with `status CHECK('draft','open','closed')`

---

## Endpoint overview

| Method | Path | What it does |
|--------|------|--------------|
| GET | `/api/admin/companies` | List all companies; accepts `?status=` filter |
| PATCH | `/api/admin/companies/:id/verify` | Set status to `verified` |
| PATCH | `/api/admin/companies/:id/suspend` | Set status to `suspended`; close open jobs; purge cache |

All three require `authMiddleware` → `requireRole('admin')` — the router is already guarded at
mount time, so individual routes inherit it automatically.

## Implementation

### admin.repo.ts

```ts
import db from '../../shared/db';

// List companies; optionally filter by status
export async function listCompanies(status?: string) {
  const conditions: string[] = [];
  const params: unknown[] = [];

  if (status) {
    params.push(status);
    conditions.push(`c.status = $${params.length}`);
  }

  const where = conditions.length ? `WHERE ${conditions.join(' AND ')}` : '';

  const result = await db.query(
    `SELECT c.id, c.name, c.status, c.created_at, u.email AS owner_email
     FROM companies c
     JOIN users u ON u.id = c.owner_id
     ${where}
     ORDER BY c.created_at DESC`,
    params
  );
  return result.rows;
}

// Find a single company by id
export async function findCompanyById(id: string) {
  const result = await db.query(
    `SELECT id, name, status FROM companies WHERE id = $1`,
    [id]
  );
  return result.rows[0] ?? null;
}

// Set company status and return updated row
export async function setCompanyStatus(id: string, status: string) {
  const result = await db.query(
    `UPDATE companies SET status = $1 WHERE id = $2
     RETURNING id, name, status`,
    [status, id]
  );
  return result.rows[0] ?? null;
}

// Close all open jobs for a company (called on suspension)
export async function closeOpenJobsForCompany(companyId: string) {
  await db.query(
    `UPDATE jobs SET status = 'closed'
     WHERE company_id = $1 AND status = 'open'`,
    [companyId]
  );
}
```

### admin.service.ts

```ts
import * as repo from './admin.repo';
import { redis } from '../../shared/redis';
import { NotFoundError, ConflictError } from '../../shared/errors';

export async function listCompanies(status?: string) {
  return repo.listCompanies(status);
}

export async function verifyCompany(id: string) {
  const company = await repo.findCompanyById(id);
  if (!company) throw new NotFoundError('Company not found');
  if (company.status === 'verified') throw new ConflictError('Company is already verified');

  const updated = await repo.setCompanyStatus(id, 'verified');
  return updated;
}

export async function suspendCompany(id: string) {
  const company = await repo.findCompanyById(id);
  if (!company) throw new NotFoundError('Company not found');
  if (company.status === 'suspended') throw new ConflictError('Company is already suspended');

  const updated = await repo.setCompanyStatus(id, 'suspended');

  // Close all open jobs for this company
  await repo.closeOpenJobsForCompany(id);

  // Purge the public job-board cache (same key as ch45)
  await redis.del('jobs:public:page1');

  return updated;
}
```

### admin.routes.ts (company section)

```ts
import { Router } from 'express';
import * as service from './admin.service';

const router = Router();
// authMiddleware + requireRole('admin') are applied at mount time in app.ts

router.get('/companies', async (req, res, next) => {
  try {
    const companies = await service.listCompanies(req.query.status as string | undefined);
    res.json({ companies });
  } catch (err) {
    next(err);
  }
});

router.patch('/companies/:id/verify', async (req, res, next) => {
  try {
    const company = await service.verifyCompany(req.params.id);
    res.json({ company });
  } catch (err) {
    next(err);
  }
});

router.patch('/companies/:id/suspend', async (req, res, next) => {
  try {
    const company = await service.suspendCompany(req.params.id);
    res.json({ company });
  } catch (err) {
    next(err);
  }
});

export default router;
```

## The 409 logic

The service checks current status before writing. If the action is already in effect, it throws
`ConflictError` which the global error handler maps to HTTP 409. This prevents no-op writes and
gives the admin clear feedback.

```
already verified → PATCH /verify  → 409 Conflict
already suspended → PATCH /suspend → 409 Conflict
not found       → either PATCH    → 404 Not Found
```

---

## Cache invalidation on suspend

When a company is suspended, its jobs are closed. The public job board cache (`jobs:public:page1`)
may still contain those jobs. Deleting the key forces the next GET to re-query PostgreSQL and
return only open jobs. This is the same pattern from Chapter 45.

Only page 1 is deleted here because cursor-based subsequent pages are keyed differently and will
naturally be evicted when they expire. In production, you would delete all keys matching
`jobs:public:*` using `redis.keys` + `redis.del`.
