# What migrations are

## The problem with ad-hoc SQL

Running `CREATE TABLE` statements by hand works once, on one machine. It breaks as soon as:

- A second developer joins and needs to reproduce your schema
- You make a change (add a column, add an index) and need that change applied to staging and production without recreating the database
- You need to know exactly what version of the schema a given environment is running

The solution is versioned migration files — SQL (or code that generates SQL) committed to the repo like any other file, run in a defined order, tracked so the same file is never applied twice.

## What a migration file is

A migration file is one unit of schema change. An initial setup might have seven migration files — one per table, in dependency order. Adding a column later is one more file. Each file has:

- **An `up` function** — the change to apply (create table, add column, create index)
- **A `down` function** — how to undo it (drop table, drop column, drop index)

The `down` function is useful in development (roll back a bad migration, fix it, re-apply). In production, running `down` is rare and usually done deliberately rather than automatically.

## How the tool tracks state

`node-pg-migrate` — the tool used in this project — maintains a table called `pgmigrations` in your database. Every time you run `up`, it checks which migration files have already been recorded in that table and runs only the ones that haven't. When a migration succeeds, it inserts a row. You never need to manage this table manually.

## Migration file naming

`node-pg-migrate` names files with a timestamp prefix by default: `1732000001_create_users.ts`. The timestamp guarantees that two developers working on different features in parallel will produce files that sort into a deterministic order when merged — no manual renaming. Sequential numbers (001, 002) break when two people create a migration simultaneously: both write `008_...` and one has to be renamed before merging.

The prefix is the sort key. The name after the prefix is documentation.
