# Setting up node-pg-migrate

## Install

`pg` is already installed from [Chapter 6](../06-config-and-secrets/). Add `node-pg-migrate` as a dev dependency — it is a build-time tool, never imported in production code:

```bash
npm install --save-dev node-pg-migrate
```

## Add npm scripts

`node-pg-migrate` cannot execute TypeScript files on its own — it needs to run through `tsx`, which is already in your project from [Chapter 4](../04-project-bootstrap/). Open `package.json` and add three scripts:

```json
{
  "scripts": {
    "migrate": "tsx node_modules/node-pg-migrate/bin/node-pg-migrate up",
    "migrate:down": "tsx node_modules/node-pg-migrate/bin/node-pg-migrate down 1",
    "migrate:create": "node-pg-migrate create --migration-file-language ts"
  }
}
```

- `npm run migrate` — applies all pending migrations in order
- `npm run migrate:down` — rolls back the most recent migration (pass a number to roll back more; e.g. `migrate:down 3`)
- `npm run migrate:create -- <name>` — generates a new timestamped migration file with up/down stubs (example: `npm run migrate:create -- create_users`)

The `migrate:create` command doesn't execute TypeScript — it only writes a file — so it doesn't need `tsx`.

## Configuration

`node-pg-migrate` picks up `DATABASE_URL` from the environment automatically — the same value already in your `.env` from Chapter 6. No additional config file is needed.

## Create the migrations directory

Create `migrations/` at the project root (alongside `src/`):

```bash
mkdir migrations
```

## Verify the setup

Run `npm run migrate` now — with an empty `migrations/` directory and a running database, the tool will create the `pgmigrations` tracking table and report that there are no pending migrations to apply. If you see a connection error instead, confirm your Docker PostgreSQL container is running and that `DATABASE_URL` in `.env` is correct.
