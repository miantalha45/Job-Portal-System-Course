# Chapter 24 — Prerequisites and framing

## What you need in place

**Chapter 17 — `ForbiddenError` exists** in `src/shared/errors.ts` with `statusCode: 403` and `code: 'FORBIDDEN'`. The role gate throws it.

**Chapter 21 — `authMiddleware` exists** at `src/shared/auth-middleware.ts`. It verifies the Bearer token, attaches `req.user = { userId, role }`, and throws `UnauthorizedError` when the token is missing or invalid. `src/types/express.d.ts` already extends `Express.Request` with the `user` property.

**Chapter 23 — The full auth flow is complete.** `POST /auth/register`, `POST /auth/verify-email`, `POST /auth/resend-verification`, `POST /auth/login`, `POST /auth/refresh`, and `POST /auth/logout` all work. Run `npx tsc --noEmit` and confirm zero errors before you start.

## What this chapter builds

One file: `src/shared/require-role.ts`.

`requireRole` is a middleware factory. You call it with one or more role strings and it returns an Express middleware function that allows the request through if the authenticated user's role matches, and throws `ForbiddenError` otherwise.

This is the last piece of the auth module. After this chapter, any route in the system can be protected with two middleware calls in sequence: `authMiddleware` then `requireRole(...)`.

Chapter 25 covers the concept distinction between authentication and authorization. Chapter 26 applies both middleware across all the role-gated routes in the system. This chapter focuses entirely on building and verifying `requireRole`.
