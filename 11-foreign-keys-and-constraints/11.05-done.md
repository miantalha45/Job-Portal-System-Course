# Definition of done — Chapter 11

This is a design chapter. There is no code to run — the output is your updated learning-log DDL and written reflections on the FK decisions you made.

## Checklist

- [ ] **Your learning-log DDL for chapters 8–10 includes the `ON DELETE` clauses** from the complete FK summary in chapter 11.03. If you have not added them yet, do it now before moving on.

- [ ] **In your learning log, write one sentence for each of the four `ON DELETE` behaviours** (`NO ACTION`, `RESTRICT`, `CASCADE`, `SET NULL`) explaining when you would choose it. If you cannot write a sentence without re-reading the chapter, re-read it.

- [ ] **In your learning log, write a brief note on the applicant account deletion problem**: what does `RESTRICT` on `applications.applicant_id` force the application layer to do before the delete can proceed? Name the two paths (anonymise vs hard-delete) and which FK behaviour each one uses.

- [ ] **In your learning log, give one example of a rule in this portal** that looks like it belongs in a `CHECK` constraint but actually belongs in the validation layer, and explain why.

## Log it

1. Which FK decision in this chapter required the most careful reasoning? What does `RESTRICT` protect against in that specific case?
2. Describe a scenario in this portal where a developer might feel tempted to add `ON DELETE CASCADE` to a FK that this chapter classifies as `RESTRICT`. What would happen if they did?
