# Chapter 49 — The Application Shortlist

## What you will build

Three endpoints that let an applicant bookmark jobs they are interested in before applying. The shortlist is private to each applicant and scoped by `applicantId`.

## Learning goals

- Use a junction table with a composite UNIQUE constraint to prevent duplicates
- Handle `23505` unique violations as `ConflictError` rather than letting them surface as 500s
- JOIN across `shortlist_items`, `jobs`, and `companies` for a useful list response

## Prerequisites

- Chapter 46: applicant profile in place (`applicantId` lookup from `userId`)
- `shortlist_items` table exists in your schema (see below)
- `jobs` and `companies` tables from Chapters 9 and 36

## Schema reminder

```sql
CREATE TABLE shortlist_items (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  applicant_id uuid REFERENCES applicants(id) NOT NULL,
  job_id       uuid REFERENCES jobs(id) NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  UNIQUE(applicant_id, job_id)
);
```

## Endpoint summary

| Method | Path                               | Description                       |
|--------|------------------------------------|-----------------------------------|
| POST   | /api/applicants/shortlist          | Add a job to shortlist            |
| GET    | /api/applicants/shortlist          | List shortlisted jobs             |
| DELETE | /api/applicants/shortlist/:jobId   | Remove a job from shortlist       |

All routes require `requireAuth` + `requireRole('applicant')`.

---

## Constraints enforced

1. **Job must exist and be open** — if `job_id` does not exist or `jobs.status != 'open'`, return `404 Not Found`.
2. **Duplicate prevention** — the `UNIQUE(applicant_id, job_id)` constraint prevents the same job appearing twice. Catch PostgreSQL error code `23505` and throw `ConflictError`.
3. **Limit 100 items** — check the current count before inserting. If `>= 100`, throw a `400 Bad Request` with a clear message.
4. **Ownership on DELETE** — the WHERE clause always includes `applicant_id = $applicantId` so an applicant cannot remove another applicant's shortlist item.

## Implementation

### applicants.repo.ts — shortlist functions

```ts
export async function addToShortlist(applicantId: string, jobId: string) {
  // Verify job exists and is open
  const job = await db.query(
    `SELECT id FROM jobs WHERE id = $1 AND status = 'open'`,
    [jobId]
  );
  if (job.rowCount === 0) throw new NotFoundError('Job not found or not open');

  // Check limit
  const count = await db.query(
    `SELECT COUNT(*) FROM shortlist_items WHERE applicant_id = $1`,
    [applicantId]
  );
  if (parseInt(count.rows[0].count, 10) >= 100) {
    throw new ValidationError('Shortlist limit of 100 items reached');
  }

  const result = await db.query(
    `INSERT INTO shortlist_items (applicant_id, job_id)
     VALUES ($1, $2)
     RETURNING id, applicant_id, job_id, created_at`,
    [applicantId, jobId]
  );
  return result.rows[0];
}

export async function listShortlist(applicantId: string) {
  const result = await db.query(
    `SELECT
       si.id,
       si.job_id,
       si.created_at,
       j.title,
       j.status AS job_status,
       j.created_at AS job_created_at,
       c.id   AS company_id,
       c.name AS company_name
     FROM shortlist_items si
     JOIN jobs      j ON j.id = si.job_id
     JOIN companies c ON c.id = j.company_id
     WHERE si.applicant_id = $1
     ORDER BY si.created_at DESC
     LIMIT 100`,
    [applicantId]
  );
  return result.rows;
}

export async function removeFromShortlist(applicantId: string, jobId: string) {
  const result = await db.query(
    `DELETE FROM shortlist_items
     WHERE applicant_id = $1 AND job_id = $2
     RETURNING id`,
    [applicantId, jobId]
  );
  if (result.rowCount === 0) throw new NotFoundError('Shortlist item not found');
}
```

### applicants.service.ts — shortlist functions

```ts
export async function addJobToShortlist(userId: string, jobId: string) {
  const profile = await repo.findApplicantByUserId(userId);
  if (!profile) throw new NotFoundError('Profile not found');

  try {
    return await repo.addToShortlist(profile.id, jobId);
  } catch (err: any) {
    if (err.code === '23505') throw new ConflictError('Job already in shortlist');
    throw err;
  }
}

export async function getShortlist(userId: string) {
  const profile = await repo.findApplicantByUserId(userId);
  if (!profile) throw new NotFoundError('Profile not found');
  return repo.listShortlist(profile.id);
}

export async function removeJobFromShortlist(userId: string, jobId: string) {
  const profile = await repo.findApplicantByUserId(userId);
  if (!profile) throw new NotFoundError('Profile not found');
  await repo.removeFromShortlist(profile.id, jobId);
}
```

### applicants.routes.ts — shortlist routes

```ts
router.post('/shortlist', async (req, res, next) => {
  try {
    const { jobId } = req.body;
    const item = await service.addJobToShortlist(req.user!.userId, jobId);
    res.status(201).json(item);
  } catch (err) {
    next(err);
  }
});

router.get('/shortlist', async (req, res, next) => {
  try {
    const items = await service.getShortlist(req.user!.userId);
    res.json({ shortlist: items });
  } catch (err) {
    next(err);
  }
});

router.delete('/shortlist/:jobId', async (req, res, next) => {
  try {
    await service.removeJobFromShortlist(req.user!.userId, req.params.jobId);
    res.status(204).send();
  } catch (err) {
    next(err);
  }
});
```

## Why no pagination?

The shortlist is limited to 100 items by a hard limit enforced before insert. With at most 100 rows per applicant, the response is always small. The query uses `LIMIT 100` as a safety net, but pagination adds complexity with no real benefit here.

## No `process.env` in this module

All database access goes through `db` from `src/shared/db`. Config values are sourced from `config.ts` only.
