```bash
  -H "Content-Type: application/json" \

# 4. Confirm the worker log shows a failure then a success (retry)
# Worker terminal should show:
# [worker] Job failed: send-application-confirmation ... SMTP timeout (simulated)

# [worker] Job completed: send-application-confirmation ...

# 5. Confirm no jobs in the failed set after a successful retry
npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  const failed = await queue.getFailed(0, 10);
  console.log('Failed jobs:', failed.length);
  await queue.close();
})();
"
# Expected: "Failed jobs: 0"

# 6. Force all retries to fail (set failCount = 5 temporarily)
#    Submit another application and watch the worker exhaust retries

npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  const failed = await queue.getFailed(0, 10);
  console.log('Failed jobs:', failed.length);
  if (failed[0]) {
    console.log('Reason:', failed[0].failedReason);
    console.log('Attempts made:', failed[0].attemptsMade);
  }
  await queue.close();
})();
"
# Expected: Failed jobs: 1, Attempts made: 3

# 7. Confirm removeOnComplete and removeOnFail are set
grep -n 'removeOnComplete\|removeOnFail' src/shared/queue.ts
# Expected: both present with count values

# 8. Remove the deliberate failure from mailer.ts and re-verify compilation
npx tsc --noEmit
# Expected: no errors

# 9. Confirm that a retry with ON CONFLICT DO NOTHING is idempotent
#    (Conceptual verification — no command needed if no DB-write job exists yet)

```

## Quiz

1. BullMQ is configured with `{ attempts: 3, backoff: { type: 'exponential', delay: 1000 } }`.
   A job fails on attempt 1 (T=0), attempt 2 (T=1s), and attempt 3 (T=3s). After T=3s the job
   is in the `failed` set. A developer calls `await failedJob.retry()` at T=10s. What happens
   next, and what is the maximum number of times the job will now run in total?

2. A `'send-welcome-email'` job is sent twice with the same payload (because the user clicked
   "Register" twice in under a second). Both jobs complete successfully. The user receives two
   welcome emails. Without changing the frontend, how would you prevent the duplicate email
   using BullMQ's `jobId` option?

3. A job inserts a row into a `notifications` table, then calls an external push notification
   service. The DB insert succeeds but the push notification call throws on the first attempt.
   On retry, the DB insert hits `ON CONFLICT DO NOTHING`. The push notification call succeeds.
   Is the overall job idempotent? What is the push notification service responsible for to make
   this work correctly?
