# Chapter 66 — Definition of Done

## Verifiable checklist

```bash
# 1. Migration applied successfully
psql $DATABASE_URL -c "\d resumes" | grep word_count
# Expected: word_count | integer | nullable

# 2. TypeScript compiles with zero errors
npx tsc --noEmit

# 3. processResume handler file exists
ls src/worker/handlers/processResume.ts
# Expected: file listed

# 4. Start the API and worker
# Terminal 1: npm run dev
# Terminal 2: npm run worker

# 5. Upload a résumé file
RESUME_ID=$(curl -s -X POST http://localhost:3000/api/applicants/profile/resume \
  -H "Authorization: Bearer $APPLICANT_TOKEN" \
  -F "resume=@/path/to/sample.txt" \
  | jq -r '.resume.id')
echo "Resume ID: $RESUME_ID"
# Expected: a UUID

# 6. Check that word_count is null immediately after upload (before worker runs)
psql $DATABASE_URL -c \
  "SELECT word_count FROM resumes WHERE id = '$RESUME_ID';"
# Expected: word_count is NULL (worker hasn't run yet if checked fast enough)

# 7. Wait for worker to process, then re-check
sleep 3
psql $DATABASE_URL -c \
  "SELECT word_count FROM resumes WHERE id = '$RESUME_ID';"
# Expected: word_count is a non-null integer > 0

# 8. Confirm the job is in the completed set (not failed)
npx ts-node -e "
import queue from './src/shared/queue';
(async () => {
  const completed = await queue.getCompleted(0, 10);
  const found = completed.find(j => j.name === 'process-resume');
  console.log('process-resume completed:', !!found);
  await queue.close();
})();
"
# Expected: "process-resume completed: true"

# 9. Confirm no process.env in the handler
grep 'process\.env' src/worker/handlers/processResume.ts
# Expected: no output

# 10. Confirm the UPDATE is parameterized (not string interpolation)
grep '\$1\|\$2' src/worker/handlers/processResume.ts
# Expected: lines containing $1 and $2 placeholders
```

## Quiz

1. The `processResume` handler runs `UPDATE resumes SET word_count = $1 WHERE id = $2`. If the
   résumé row is deleted from the database between the time the job was enqueued and the time
   the worker runs, the UPDATE affects 0 rows. The handler does not throw. BullMQ marks the job
   as completed. Is this the correct behaviour? Should the handler check `rowCount` and throw if
   0 rows were updated? Justify your answer with reference to idempotency.

2. A developer suggests storing the word count in a Redis key instead of the `resumes` table, so
   the worker does not need a DB write. List two consequences of this approach for data durability
   and system consistency.

3. The word count for a PDF résumé is much lower than the actual word count because most of the
   binary content is not valid UTF-8 text. How would you fix this without changing the overall
   async processing architecture? Name the npm package that would replace the raw buffer parsing.
