# Invitation Flow

## Why invitations instead of open registration?

A recruiter cannot simply register and pick a company to join. Company membership is controlled by the company. The owner or HR manager must explicitly invite a colleague by email. This prevents a competitor from registering and claiming membership in your company.

The invitation is the proof of authorization. When the invitee accepts it, they are not just signing up for an account — they are proving they received the email sent to the address the company trusted.

---

## The full invitation lifecycle

```
Owner calls POST /api/companies/invitations
  → service checks: owner or hr_manager
  → service checks: email not already a member
  → service checks: email not already invited (pending)
  → repo generates 64-char raw token
  → repo stores SHA-256 hash in invitations table
  → email sent with raw token in the link
  → 201 returned to owner

Invitee receives email, clicks link:
  → link is POST /auth/accept-invitation?token=<raw>
  → acceptance handled in Chapter 34
```

The `invitations` table row stays in place until the invitee accepts. On acceptance, the row is deleted. If the invitation expires (`expires_at < NOW()`), it is ignored in all lookups.

---

## What the owner sees

```bash
POST /api/companies/invitations
Authorization: Bearer <owner-token>
Content-Type: application/json

{
  "email": "colleague@example.com",
  "role": "hr_manager"
}
```

Successful response:

```json
{ "message": "Invitation sent." }
```

HTTP status: `201`.

The response intentionally reveals no information about the token. The raw token travels only via email. The owner knows the invitation was sent; they do not need the token.

---

## Conflict cases

**Email already a member:**

```json
{ "error": "This person is already a member of your company." }
```

HTTP status: `409`.

**Pending invitation exists:**

```json
{ "error": "A pending invitation for this email already exists." }
```

HTTP status: `409`.

This prevents duplicate emails landing in the invitee's inbox. If the owner wants to resend, they should first cancel the old invitation (a feature you can add; it is not in this chapter's scope).

**Wrong company role (e.g., a recruiter calling this endpoint):**

```json
{ "error": "You do not have permission to perform this action." }
```

HTTP status: `403`.

**Attempting to invite as owner:**

```json
{
  "error": "Validation failed",
  "issues": [{ "field": "role", "message": "Invalid enum value..." }]
}
```

HTTP status: `422`. Zod rejects `'owner'` before the service runs.

## Token security in detail

```
rawToken   = crypto.randomBytes(32).toString('hex')    // 256 bits of entropy
tokenHash  = SHA-256(rawToken)                         // stored in DB
link       = APP_BASE_URL + '/auth/accept-invitation?token=' + rawToken
```

`APP_BASE_URL` is read from `config.ts` (which reads `process.env.APP_BASE_URL`). Only `config.ts` reads `process.env`.

The raw token has 256 bits of entropy — brute force is not feasible. The invitation expires in `INVITATION_EXPIRES_IN_HOURS` hours (default 72), further limiting the window for an attacker who intercepts the email.

---

## Expiry handling

The `expires_at` column is set at INSERT time:

```sql
NOW() + ($6 || ' hours')::interval
```

where `$6` is the string representation of `config.INVITATION_EXPIRES_IN_HOURS`. All queries that look up invitations include `AND expires_at > NOW()`. An expired invitation is invisible to the system — it does not produce a 403 or a helpful message; the token lookup simply returns null, which the accept-invitation handler (Chapter 34) will treat as an invalid token.

Expired rows accumulate in the table. A periodic cleanup job (a simple `DELETE FROM invitations WHERE expires_at < NOW()`) keeps the table tidy. That job is not built in this chapter but should be added before production.

## Checking your work (before Chapter 34)

After sending an invitation, verify the row exists and the hash is stored:

```sql
SELECT id, email, role, expires_at,
       length(token_hash) AS hash_length
FROM invitations
WHERE email = 'colleague@example.com';
```

Expected: one row. `hash_length` is 64 (SHA-256 hex = 64 characters). The raw token is not in the row.

Confirm `expires_at` is approximately 72 hours from now:

```sql
SELECT expires_at - NOW() AS time_remaining
FROM invitations
WHERE email = 'colleague@example.com';
```
