# Guidelines — Chapter 33

## Before you start

- **Chapter 31** — the `companies` and `recruiters` tables exist; the owner's recruiter row is in place; `getRecruiterCompany(userId)` returns `{ companyId, companyRole }`.
- **Chapter 32** — the `assertCompanyRole` pattern is understood. This chapter implements its first real use.
- **Email sending** — your application must already have a mail utility (introduced in Chapter 23). The invite email uses the same sender. Confirm `SMTP_*` config values are present in `config.ts` (not read from `process.env` in this file).
- The `invitations` table exists per the schema. Confirm with:

```bash
psql $DATABASE_URL -c "\d invitations"
```

Expected columns: `id`, `company_id`, `email`, `role`, `token_hash`, `expires_at`, `created_at`.

Run `npx tsc --noEmit` before you start.

## What to build

### 1. Schema — `src/modules/companies/companies.schema.ts`

```ts
export const inviteMemberSchema = z.object({
  email: z.string().email(),
  role: z.enum(['hr_manager', 'recruiter', 'hiring_manager']),
});

export type InviteMemberInput = z.infer<typeof inviteMemberSchema>;
```

Note: `'owner'` is deliberately excluded from the enum. The owner is the user who opened the workspace; that role cannot be granted through an invitation.

### 2. Repository additions — `src/modules/companies/companies.repo.ts`

```ts
import crypto from 'crypto';

export async function createInvitation(
  companyId: string,
  email: string,
  role: string,
): Promise<string> {
  const rawToken = crypto.randomBytes(32).toString('hex');
  const tokenHash = crypto.createHash('sha256').update(rawToken).digest('hex');
  const invitationId = uuid();

  await db.query(
    `INSERT INTO invitations (id, company_id, email, role, token_hash, expires_at, created_at)
     VALUES ($1, $2, $3, $4, $5, NOW() + ($6 || ' hours')::interval, NOW())`,
    [
      invitationId,
      companyId,
      email,
      role,
      tokenHash,
      String(config.INVITATION_EXPIRES_IN_HOURS),
    ],
  );

  return rawToken; // raw token returned to the caller; only the hash is stored
}

export async function findPendingInvitation(
  companyId: string,
  email: string,
): Promise<{ id: string } | null> {
  const result = await db.query(
    `SELECT id FROM invitations
     WHERE company_id = $1 AND email = $2 AND expires_at > NOW()`,
    [companyId, email],
  );
  return result.rows[0] ?? null;
}

export async function findExistingMember(
  companyId: string,
  email: string,
): Promise<{ id: string } | null> {
  const result = await db.query(
    `SELECT r.id FROM recruiters r
     JOIN users u ON u.id = r.user_id
     WHERE r.company_id = $1 AND u.email = $2`,
    [companyId, email],
  );
  return result.rows[0] ?? null;
}
```

`config` is the default export from `../../config`. Do not read `process.env` here.

### 3. Service — `src/modules/companies/companies.service.ts`

```ts
export async function inviteMember(userId: string, input: InviteMemberInput) {
  const company = await getRecruiterCompany(userId);
  if (!company) throw new ForbiddenError('No company workspace found.');

  assertCompanyRole(company.companyRole, ['owner', 'hr_manager']);

  const existing = await findExistingMember(company.companyId, input.email);
  if (existing) throw new ConflictError('This person is already a member of your company.');

  const pending = await findPendingInvitation(company.companyId, input.email);
  if (pending) throw new ConflictError('A pending invitation for this email already exists.');

  const rawToken = await createInvitation(company.companyId, input.email, input.role);

  await sendInvitationEmail(input.email, rawToken);
}
```

`assertCompanyRole` is the helper from Chapter 32 — a plain function, not middleware:

```ts
function assertCompanyRole(companyRole: string, allowed: string[]) {
  if (!allowed.includes(companyRole)) {
    throw new ForbiddenError('You do not have permission to perform this action.');
  }
}
```

### 4. Email helper

```ts
// src/modules/companies/companies.email.ts
import { sendMail } from '../../shared/mail';
import config from '../../config';

export async function sendInvitationEmail(toEmail: string, rawToken: string) {
  const link = `${config.APP_BASE_URL}/auth/accept-invitation?token=${rawToken}`;
  await sendMail({
    to: toEmail,
    subject: 'You have been invited to join a company workspace',
    text: `You have been invited to join a company workspace. Accept your invitation here:\n\n${link}\n\nThis link expires in ${config.INVITATION_EXPIRES_IN_HOURS} hours.`,
  });
}
```

### 5. Route — `src/modules/companies/companies.routes.ts`

```ts
router.post('/invitations', async (req, res, next) => {
  try {
    const input = validate(inviteMemberSchema, req.body);
    await inviteMember(req.user!.userId, input);
    res.status(201).json({ message: 'Invitation sent.' });
  } catch (err) {
    next(err);
  }
});
```

## Token design

The raw token — 32 random bytes, hex-encoded — is 64 characters. It is generated once, immediately returned to `createInvitation`, and discarded from memory. Only its SHA-256 hash is stored in the database.

When the invitee clicks the link, `POST /auth/accept-invitation` receives the raw token in the request body, hashes it, and looks up the hash in the `invitations` table. This is the same pattern used for password-reset tokens: the database never stores a usable secret.

If an attacker reads the `invitations` table — for example, via SQL injection — they obtain only hashes. They cannot reverse the hash to the raw token.
