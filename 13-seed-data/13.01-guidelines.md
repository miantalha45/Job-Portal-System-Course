# Guidelines — Chapter 13

By the end of this chapter you will have a script that populates the database with a controlled, realistic fixture of users, companies, recruiters, applicants, jobs, and applications — data you can rely on to test every feature built in subsequent chapters.

## Before you start

The migrations from [Chapter 12](../12-migrations/) must have run cleanly. Running `npm run migrate` should show all seven migrations applied with no errors. If the database is not up or migrations haven't run, do that first.

The seed script creates and references the `scripts/` directory at the project root. Create it now if it doesn't exist:

```bash
mkdir scripts
```

The next chapter, [Chapter 14](../14-normalization-vs-denormalization/), is a design discussion — it does not build on the seed data directly. But every build chapter from [Chapter 19](../19-password-hashing-and-auth/) onwards assumes the seed users exist and are usable.

## Rethink impact

> You've run migrations. The database exists and the schema is correct. You start building the job listing endpoint. `GET /jobs` returns an empty array. You add a search feature — nothing to search. You add pagination — nothing to paginate. You add stage-filtering on the applicant view — no applications to filter. Every feature you build is tested against nothing. How much confidence does a green response from an empty database actually give you?
